## Поддерживаемые версии

Исправления выпускаются для последней версии на PyPI. Более ранние версии
обновления не получают: перейдите на последнюю.

| № | Версия                | Поддержка                        |
|---|-----------------------|----------------------------------|
| 1 | последний релиз       | исправления выпускаются          |
| 2 | предыдущие релизы     | не поддерживаются                |

## Как сообщить об уязвимости

Не заводите публичный issue: до выпуска исправления описание проблемы даёт
готовый сценарий атаки на пользователей, у которых на диске лежит ключ
авторизации от аккаунта Telegram.

Приватный канал — private vulnerability reporting на GitHub:
[Report a vulnerability](https://github.com/VitalyOstanin/tg-export/security/advisories/new).
Форма видна только сопровождающему проекта.

## Что приложить к сообщению

| № | Пункт                          | Зачем                                                   |
|---|--------------------------------|---------------------------------------------------------|
| 1 | версия пакета и Python         | воспроизведение на той же сборке                         |
| 2 | шаги воспроизведения            | без них проверка занимает несоразмерно больше времени    |
| 3 | что именно получает атакующий  | отделяет уязвимость от неудобства                        |
| 4 | предполагаемое исправление     | необязательно, но ускоряет выпуск                        |

## Чего не присылать

Реальные данные Telegram: `api_id`, `api_hash`, содержимое
`api_credentials.yaml`, файл сессии (он содержит ключ авторизации и даёт вход
в аккаунт без второго фактора), имена и идентификаторы чатов, номера
телефонов, тексты сообщений. Замените их вымышленными — для проверки
достаточно структуры.

## Что происходит дальше

Ответ на сообщение приходит в течение недели. При подтверждении уязвимости
исправление выпускается отдельным релизом, а описание проблемы публикуется
после выпуска — в CHANGELOG и в GitHub Security Advisory с указанием
сообщившего, если он не против.

## Что считается уязвимостью

Например: раскрытие ключа авторизации или учётных данных другим локальным
пользователям, выполнение произвольного кода при разборе данных из Telegram
или из чужой выгрузки, запись файлов за пределами каталога экспорта, обход
подтверждения при необратимом удалении. Ошибки, приводящие только к отказу
самой команды, уязвимостями не считаются — заводите обычный issue.

## Права доступа к файлам

Файлы, которые создаёт tg-export, доступны только владельцу -- `0600` для файлов и `0700` для
каталогов, независимо от `umask` процесса. Это относится к сессиям Telethon (файл сессии хранит
ключ авторизации: с ним другой локальный пользователь входит в аккаунт без пароля и второго
фактора), к учётным данным `api_credentials.yaml`, к глобальному `config.yaml` с логином и
паролем прокси, к базе состояния и к дереву выгрузки с текстами сообщений.

| № | Что                                    | Права  | Когда назначаются                                        |
|---|----------------------------------------|--------|----------------------------------------------------------|
| 1 | файлы сессий, учётные данные, конфиги  | `0600` | при создании файла пакетом                               |
| 2 | каталог конфигурации, каталог сессий   | `0700` | при создании каталога пакетом                            |
| 3 | файл конфигурации, написанный вручную  | `0600` | при чтении, если он доступен не только владельцу -- с предупреждением в журнале |

Каталог, который уже существует, свои права сохраняет: он мог быть открыт намеренно -- например,
чтобы отдавать выгрузку по HTTP, -- и это решение пользователя. Права проверяются и ужимаются
только у файлов, которые пакет читает как свои.
