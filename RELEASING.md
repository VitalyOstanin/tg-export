# Процесс релиза

Документ описывает конвенции выпуска версий tg-export.

## Содержание

- [Шаги релиза](#шаги-релиза)
- [Теги](#теги)
- [Публикация](#публикация)

## Шаги релиза

1. Обновить версию в `pyproject.toml`.
2. Выполнить `uv lock` и закоммитить обновлённый `uv.lock` в том же коммите (CI проверяет синхронизацию через `uv lock --check`).
3. Добавить запись в `CHANGELOG.md` (формат Keep a Changelog), дата и номер версии должны совпадать с тегом.
4. Закоммитить, создать тег (см. ниже), запушить тег -- workflow `publish.yml` соберёт пакет, прогонит тесты, выполнит smoke-тест wheel и опубликует на PyPI.

## Теги

- Релизные теги именуются `vX.Y.Z` (валидный semver).
- Создавать **аннотированные** теги, а не lightweight: `git tag -a vX.Y.Z -m "vX.Y.Z"`. Аннотированный тег хранит автора, дату и сообщение и поддерживает подпись.
- При наличии GPG/SSH-ключа подписывать тег: `git tag -s vX.Y.Z -m "vX.Y.Z"`.
- Уже опубликованные lightweight-теги (`v1.0.0`, `v1.1.0`, `v1.2.7`) не переписывать -- на них завязан запуск `publish.yml`. Конвенция действует для будущих тегов.

## Публикация

- Публикация на PyPI выполняется через Trusted Publishing (OIDC, `id-token: write` в `publish.yml`) -- долгоживущий токен PyPI не используется.
- Перед публикацией `publish.yml` прогоняет тесты и smoke-тест собранного wheel (`tg-export --version`, `tg-export --help`).
- Опционально публиковать с attestations (`pypa/gh-action-pypi-publish` поддерживает параметр `attestations`).
