## Общий вид вызова

```
tg-export [ГЛОБАЛЬНЫЕ ОПЦИИ] КОМАНДА [ОПЦИИ КОМАНДЫ] [АРГУМЕНТЫ]
```

Глобальные опции указываются до имени команды. При запуске из исходников команда
вызывается как `uv run tg-export ...`.

## Глобальные опции

| № | Опция               | Назначение                                                                        |
|---|---------------------|-----------------------------------------------------------------------------------|
| 1 | `--version`         | Показать версию и завершиться.                                                     |
| 2 | `--debug`           | Отладочное логирование (принудительно уровень `DEBUG`), перекрывает всё остальное.  |
| 3 | `--log-level LEVEL` | Уровень логирования: `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`; суффикс `:all` добавляет вывод библиотек. |
| 4 | `--quiet`, `-q`     | Подавить прогресс и статусные строки; ошибки и итоговая сводка остаются.            |
| 5 | `--help`, `-h`      | Справка по команде или группе команд.                                              |

Приоритет уровня логирования по убыванию: `--debug` > `--log-level` > переменная
окружения `LOG_LEVEL` > значение по умолчанию `WARNING`. Логи telethon и aiosqlite
держатся на `WARNING` независимо от собственного уровня и включаются суффиксом
`:all` (`--log-level DEBUG:all`).

## auth -- учётные данные и вход

### auth credentials

Сохраняет `api_id` и `api_hash`, полученные на my.telegram.org, в
`~/.config/tg-export/api_credentials.yaml`. Значения общие для всех аккаунтов.

| № | Опция             | Назначение                                                              |
|---|-------------------|-------------------------------------------------------------------------|
| 1 | `--api-id ID`     | Идентификатор приложения. Без опции запрашивается интерактивно.          |
| 2 | `--api-hash HASH` | Хеш приложения. Ввод скрыт: переданный опцией, он остаётся в истории оболочки. |

### auth add

Интерактивный вход: телефон, код подтверждения, при необходимости пароль
двухфакторной проверки. Создаёт файл сессии `sessions/<alias>.session`.

| № | Опция          | Назначение                                            |
|---|----------------|-------------------------------------------------------|
| 1 | `--name ALIAS` | Alias аккаунта. Без опции запрашивается интерактивно.  |

### auth check

Проверяет сессии: файл на месте, ключ авторизации принят сервером, аккаунт не
разлогинен. Без аргумента проверяются все аккаунты.

```bash
tg-export auth check                      # все аккаунты
tg-export auth check myaccount --json
tg-export auth check --account myaccount  # то же самое
```

| № | Опция       | Назначение                                                             |
|---|-------------|------------------------------------------------------------------------|
| 1 | `--json`    | Машиночитаемый вывод: в stdout только JSON.                             |
| 2 | `--account` | Аккаунт; то же, что позиционное `NAME`. Два разных значения -- ошибка `2`. |

Возвращает `1`, если хотя бы одна проверенная сессия непригодна.

## account -- управление аккаунтами

### account list

Перечисляет аккаунты, у которых есть файл сессии. Опция `--json` даёт
машиночитаемый вывод.

### account default

Без аргумента показывает текущий аккаунт по умолчанию, с аргументом -- задаёт его.
Аккаунт по умолчанию используется всеми командами, вызванными без `--account`.

В stdout уходит только само имя аккаунта, пояснение -- в stderr, поэтому
подстановка вида `NAME=$(tg-export account default)` даёт alias без разбора
строки. Когда аккаунт по умолчанию не задан, stdout пуст, пояснение приходит в
stderr, а код возврата остаётся `0` -- как у `account list` без аккаунтов.
С `--json` печатается объект `{"default": <alias или null>}` -- и при показе, и после задания.

```bash
tg-export account default            # показать
tg-export account default --json     # {"default": "myaccount"}
tg-export account default myaccount  # задать
tg-export account default myaccount --json  # задать и напечатать {"default": "myaccount"}
```

### account remove

Удаляет файл сессии аккаунта. Конфигурация аккаунта и уже сделанная выгрузка
остаются на диске. Возвращает `1`, если аккаунта с таким именем нет.

## config -- показать конфигурацию

Печатает действующие настройки: глобальные (прокси, минимум свободного места) и
по каждому аккаунту, у которого есть файл конфигурации.

| № | Опция             | Назначение                                              |
|---|-------------------|---------------------------------------------------------|
| 1 | `--verbose`, `-v` | Дополнительно показать правила отбора чатов по аккаунтам |
| 2 | `--json`          | Машиночитаемый вывод: каталог конфигурации, прокси, действующий минимум свободного места, число свободных байт, `api_id` и список аккаунтов. С `-v` у каждого аккаунта появляется блок `settings` (каталог и формат выгрузки, типы медиа, предел размера файла, число параллельных загрузок). `api_hash` в этот вывод не попадает: четыре его знака в терминале служат тому, чтобы отличить одни учётные данные от других, и разбирающей программе не нужны. |

## list -- каталог чатов и папок

Запрашивает список диалогов и папок и записывает каталог, из которого затем
строится конфигурация (`init --from-catalog`) или берутся идентификаторы для `tg info`.

```bash
tg-export list --output-file catalog.yaml
tg-export list --json --include-left --output-file catalog.json
```

| № | Опция                 | Назначение                                                             |
|---|-----------------------|------------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт; по умолчанию -- аккаунт по умолчанию.                          |
| 2 | `--output-file FILE`  | Записать в файл. Без опции каталог печатается в stdout. Прежнее написание `--output` принимается. |
| 3 | `--json`              | Плоский JSON вместо YAML; краткая форма `--format json`. Вместе с явным `--format` -- ошибка формы вызова (код `2`): формат назван дважды. |
| 4 | `--format yaml\|json` | Формат: YAML с разделами `folders`/`unfiled`/`archived`/`left` (по умолчанию) либо плоский JSON. |
| 5 | `--include-left`      | Включить покинутые каналы и группы.                                     |

## init -- шаблон конфигурации

Создаёт `~/.config/tg-export/<alias>.yaml` с закомментированным перечнем чатов.
Без `--from-catalog` список запрашивается у Telegram, с `--from-catalog` читается из
ранее выгруженного каталога и обращения к сети не происходит.

```bash
tg-export init --account myaccount
tg-export init --account myaccount --from-catalog catalog.yaml
```

| № | Опция                 | Назначение                                                        |
|---|-----------------------|-------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт, для которого создаётся конфигурация.                      |
| 2 | `--from-catalog FILE` | Каталог, выгруженный командой `list` (YAML с разделами или JSON). Прежнее написание `--from` принимается. |
| 3 | `--output-file FILE`  | Записать конфигурацию по указанному пути вместо пути по конвенции. Прежнее написание `--output` принимается. |
| 4 | `--force`             | Перезаписать существующую конфигурацию; прежняя сохраняется рядом как `<имя>.bak`. |

Существующая конфигурация не перезаписывается: команда завершается кодом 1 и
называет путь. Список чатов со временем меняется, поэтому повторный `init` для
его обновления ожидаем, а написанные руками правила по папкам, лимиты и даты
восстановить неоткуда -- в отличие от сессии и каталога чатов.

## run -- экспорт

Выполняет экспорт по конфигурации аккаунта. При повторном запуске скачиваются
только новые сообщения и файлы.

```bash
tg-export run
tg-export run --dry-run
tg-export run --require-takeout --verify
tg-export run --no-takeout
```

| № | Опция               | Назначение                                                                     |
|---|---------------------|--------------------------------------------------------------------------------|
| 1 | `--account ALIAS`   | Аккаунт; по умолчанию -- аккаунт по умолчанию.                                  |
| 2 | `--config FILE`     | Файл конфигурации вместо пути по конвенции.                                     |
| 3 | `--output DIR`      | Каталог экспорта целиком, вместо `output.path` из конфигурации.                  |
| 4 | `--verify`          | После экспорта проверить целостность скачанных файлов.                          |
| 5 | `--dry-run`         | Показать, что было бы выгружено, ничего не скачивая.                            |
| 6 | `--require-takeout` | Считать недоступность Takeout ошибкой, а не переходить на обычный API.          |
| 7 | `--no-takeout`      | Не запрашивать Takeout вовсе; экспорт идёт через обычный API.                    |
| 8 | `--rerender`        | Пересобрать HTML всех чатов, включая те, в которых ничего не изменилось.         |

Ctrl+C сохраняет состояние и завершает процесс кодом `130`; повторный Ctrl+C
в течение трёх секунд прерывает немедленно. Позже этого окна второй Ctrl+C
читается как новая просьба остановиться мягко: случайное двойное нажатие не
должно отменять чат, который в этот момент сохраняется.

Страницы чата пересобираются только тогда, когда прогон что-то в него записал:
рендер каждого чата на каждом запуске означал перечитывание всей базы. Из этого
следует, что после обновления tg-export страницы чатов без новых сообщений
остаются собранными прежней версией шаблонов. `tg-export run --rerender`
пересобирает HTML всех чатов из базы, не обращаясь к Telegram за сообщениями
повторно.

## state -- состояние экспорта

### state show

Показывает по каждому чату: сколько сообщений сохранено, до какого идентификатора
дошёл обход, когда состояние обновлялось в последний раз. С аргументом
`CHAT_ID` -- только по одному чату.

| № | Опция             | Назначение                                        |
|---|-------------------|---------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                          |
| 2 | `--config FILE`   | Файл конфигурации вместо пути по конвенции.        |
| 3 | `--output DIR`    | Каталог экспорта вместо взятого из конфигурации.    |
| 4 | `--json`          | Машиночитаемый вывод: в stdout только JSON.        |

### state reset

Сбрасывает указатели обхода, чтобы следующий запуск перечитал чат с начала.
Сообщения и файлы при этом сохраняются, если не задан `--delete-messages`.
Сброс без него обратим: он стоит повторной выгрузки, а не данных.

Вопрос задаётся во всех случаях, кроме сброса одного чата без
`--delete-messages`: `--all` затрагивает все чаты сразу, поэтому подтверждение
запрашивается и для обратимого сброса. Пропустить вопрос -- `--yes`.

```bash
tg-export state reset 123456789
tg-export state reset --all
tg-export state reset --all --delete-messages --yes
```

| № | Опция                | Назначение                                                   |
|---|----------------------|--------------------------------------------------------------|
| 1 | `--all`              | Сбросить состояние всех чатов.                                |
| 2 | `--delete-messages`  | Дополнительно удалить сохранённые сообщения и записи о файлах из базы. Необратимо: перед удалением печатается число затрагиваемых строк по таблицам и запрашивается подтверждение -- и для одного чата, и для `--all`. |
| 3 | `--yes`              | Не спрашивать подтверждение необратимого сброса -- для автоматизации. |
| 4 | `--account`, `--config`, `--output` | Как у `state show`.                            |

## purge -- удалить данные чата

Удаляет данные чата: сообщения и записи о файлах из базы, скачанные файлы и
готовые HTML-страницы с диска. Аргументом принимается идентификатор чата либо
часть названия -- в последнем случае перед удалением показывается найденный чат.

```bash
tg-export purge 123456789
tg-export purge "Рабочий чат" --yes
```

| № | Опция             | Назначение                                          |
|---|-------------------|-----------------------------------------------------|
| 1 | `--yes`           | Не спрашивать подтверждения.                        |
| 2 | `--account`, `--config`, `--output` | Как у `state show`.               |

Перед удалением печатается, сколько записей в каждой таблице будет удалено.

## verify -- проверка скачанных файлов

Сверяет скачанные файлы с записями в базе: файл на месте, размер совпадает.
Битые и отсутствующие файлы скачиваются заново -- во временный каталог рядом с
целевым, с заменой оригинала только после успеха, поэтому обрыв связи не
уничтожает имеющийся файл. Возвращает `1`, если перекачать удалось не всё.

| № | Опция                                | Назначение                    |
|---|--------------------------------------|-------------------------------|
| 1 | `--account`, `--config`, `--output`  | Как у `state show`.           |

## takeout -- сессии Takeout

### takeout clear

Завершает Takeout-сессию на сервере и стирает её идентификатор из файла сессии.
Нужна, когда сохранённый идентификатор мешает: например, требуется начать
выгрузку с другими параметрами Takeout. В обычной работе не требуется --
сессия переиспользуется между запусками намеренно, см. раздел про Takeout в
[README](../README.md).

Если сервер не отвечает (обрыв связи, таймаут), идентификатор остаётся на месте, а
команда завершается кодом `1`: сессия могла остаться запущенной, и сохранённый
идентификатор -- единственный способ к ней вернуться. Повторите команду, когда связь
восстановится. Отказ сервера по существу означает, что сессии там уже нет, и
идентификатор стирается локально.

Аргумент `NAME` задаёт аккаунт; то же значение принимает опция `--account`, общая
с остальными командами. Без них берётся аккаунт по умолчанию; указание двух разных
имён сразу -- ошибка `2`.

## tg -- прямые запросы к Telegram

Команды группы не связаны с экспортом и не пишут в базу состояния.

### tg messages

Печатает последние сообщения чата.

```bash
tg-export tg messages 123456789 -n 20 --no-truncate
```

| № | Опция             | Назначение                                                    |
|---|-------------------|---------------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                                      |
| 2 | `--limit`, `-n`   | Сколько сообщений показать (по умолчанию 10).                  |
| 3 | `--truncate N`    | Обрезать текст до N символов (`0` -- не обрезать, по умолчанию 200). |
| 4 | `--no-truncate`   | Печатать текст полностью.                                      |
| 5 | `--json`          | Машиночитаемый вывод: в stdout массив объектов `id`, `date`, `sender`, `text`, `media`, `action`; заголовок чата уходит в stderr. Обрезка при этом по умолчанию не применяется -- она нужна терминалу; `--truncate N` действует и здесь. Тип медиа и вид системного сообщения стоят отдельными полями, а не приписываются к тексту. |

### tg info

Сведения о чатах: тип, название, число сообщений. Принимает один или несколько
идентификаторов либо каталог с фильтром по типу.

```bash
tg-export tg info 123456789 987654321
tg-export tg info --from-catalog catalog.json --type personal -n 3 --output-file info.json
```

| № | Опция                 | Назначение                                                        |
|---|-----------------------|-------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт.                                                          |
| 2 | `--from-catalog FILE` | Каталог в JSON (`list --json`) вместо перечня идентификаторов.     |
| 3 | `--type TYPE`         | Отбор по типу чата; только вместе с `--from-catalog`, иначе ошибка формы вызова (код `2`). |
| 4 | `--limit N`, `-n N`   | Дополнительно показать последние N сообщений каждого чата. Прежнее написание `--last` принимается. |
| 5 | `--output-file FILE`  | Записать результат в JSON-файл. Прежнее написание `--output` принимается. |
| 6 | `--json`              | Машиночитаемый вывод: в stdout только JSON-документ.                |

Возвращает `1`, если хотя бы один чат опросить не удалось, и `2`, если не заданы ни
идентификаторы, ни `--from-catalog`: собрать вызов не из чего. Фильтр `--from-catalog --type`,
не подобравший ни одного чата, -- законный пустой результат: код `0`, а под `--json` в stdout
печатается `[]`. Счётчик обработанных чатов и сообщения об ошибках идут в stderr, поэтому вывод
команды пригоден для конвейера.

### tg send

Отправляет сообщение и файлы одному или нескольким получателям (идентификаторы
или имена пользователей). Требуется хотя бы `--text`, `--text-file` или `--file`.

```bash
tg-export tg send myfriend --text "Привет"
tg-export tg send myfriend --text-file letter.txt
echo "Привет" | tg-export tg send myfriend --text-file -
tg-export tg send 123456789 --file photo.jpg --file video.mp4 --as-document
```

| № | Опция               | Назначение                                                             |
|---|---------------------|------------------------------------------------------------------------|
| 1 | `--account ALIAS`   | Аккаунт, от имени которого идёт отправка.                               |
| 2 | `--text`, `-t`      | Текст сообщения. Попадает в командную строку, видимую другим локальным пользователям и истории оболочки. |
| 3 | `--text-file PATH`  | Прочитать текст из файла, а при значении `-` -- со стандартного ввода: текст не проходит через командную строку. |
| 4 | `--file`, `-f`      | Файл вложения; опцию можно повторять.                                   |
| 5 | `--as-document`     | Отправить файлы без сжатия, как документы: изображения и видео сохраняют исходное качество. |

Команду нельзя запускать, пока идёт экспорт того же аккаунта: файл сессии
рассчитан на одного пользователя, и попытка будет отклонена с указанием, какой
процесс его занял. Возвращает `1`, если хотя бы один получатель не получил сообщение.

### tg download

Скачивает содержимое одного сообщения: текст в `<msg_id>.txt` и все медиафайлы.

```bash
tg-export tg download 123456789 4242 --output ./downloads
```

| № | Опция             | Назначение                                              |
|---|-------------------|---------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                                |
| 2 | `--output`, `-o`  | Каталог для сохранения (по умолчанию текущий).           |
| 3 | `--json`          | Машиночитаемый вывод: в stdout документ `{"chat_id": ..., "msg_id": ..., "text_file": ..., "media": [...]}` с путями сохранённых файлов. |

Имена файлов выбирает Telegram, поэтому пути -- единственный способ узнать, что именно
сохранено: `tg-export tg download 123456789 4242 --json | jq -r '.media[]'`.

Возвращает `1`, если сообщение не найдено.

## Выбор аккаунта, конфигурации и каталога

Опции повторяются в большинстве команд и разрешаются одинаково:

| № | Что выбирается        | Порядок разрешения                                                                        |
|---|-----------------------|--------------------------------------------------------------------------------------------|
| 1 | Аккаунт               | `--account` > аккаунт по умолчанию (`account default`) > ошибка с подсказкой                |
| 2 | Файл конфигурации     | `--config` > `<каталог конфигурации>/<alias>.yaml`                                          |
| 3 | Каталог конфигурации  | `TG_EXPORT_CONFIG_DIR` > `$XDG_CONFIG_HOME/tg-export` > `~/.config/tg-export`                |
| 4 | Каталог экспорта      | `--output` (путь целиком) > `output.path` из конфигурации с добавлением alias аккаунта       |
| 5 | Уровень логирования   | `--debug` > `--log-level` > `LOG_LEVEL` > `WARNING`                                          |

Подробности о каталоге экспорта и о том, когда alias не добавляется, -- в
[configuration.md](configuration.md#output).
