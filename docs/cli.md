## Общий вид вызова

```
tg-export [ГЛОБАЛЬНЫЕ ОПЦИИ] КОМАНДА [ОПЦИИ КОМАНДЫ] [АРГУМЕНТЫ]
```

Глобальные опции указываются до имени команды. При запуске из исходников команда
вызывается как `uv run tg-export ...`.

## Глобальные опции

| № | Опция               | Назначение                                                                        |
|---|---------------------|-----------------------------------------------------------------------------------|
| 1 | `--version`         | Показать версию и завершиться.                                                     |
| 2 | `--debug`           | Отладочное логирование (принудительно уровень `DEBUG`), перекрывает всё остальное.  |
| 3 | `--log-level LEVEL` | Уровень логирования: `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`; суффикс `:all` добавляет вывод библиотек. |
| 4 | `--quiet`, `-q`     | Подавить прогресс и статусные строки; ошибки и итоговая сводка остаются.            |
| 5 | `--help`, `-h`      | Справка по команде или группе команд.                                              |

Приоритет уровня логирования по убыванию: `--debug` > `--log-level` > переменная
окружения `TG_EXPORT_LOG_LEVEL` > `LOG_LEVEL` > значение по умолчанию `WARNING`.
Имя без префикса принимается ради совместимости и стоит ниже. Логи telethon и aiosqlite
держатся на `WARNING` независимо от собственного уровня и включаются суффиксом
`:all` (`--log-level DEBUG:all`).

## auth -- учётные данные и вход

### auth credentials

Сохраняет `api_id` и `api_hash`, полученные на my.telegram.org, в
`~/.config/tg-export/api_credentials.yaml`. Значения общие для всех аккаунтов.

| № | Опция             | Назначение                                                              |
|---|-------------------|-------------------------------------------------------------------------|
| 1 | `--api-id ID`     | Идентификатор приложения. Без опции запрашивается интерактивно.          |
| 2 | `--api-hash HASH` | Хеш приложения. Ввод скрыт: переданный опцией, он остаётся в истории оболочки. |

### auth add

Интерактивный вход: телефон, код подтверждения, при необходимости пароль
двухфакторной проверки. Создаёт файл сессии `sessions/<alias>.session`.

| № | Опция          | Назначение                                            |
|---|----------------|-------------------------------------------------------|
| 1 | `--name ALIAS` | Alias аккаунта. Без опции запрашивается интерактивно.  |

### auth check

Проверяет сессии: файл на месте, ключ авторизации принят сервером, аккаунт не
разлогинен. Без аргумента проверяются все аккаунты.

```bash
tg-export auth check                      # все аккаунты
tg-export auth check myaccount --json
tg-export auth check --account myaccount  # то же самое
```

| № | Опция       | Назначение                                                             |
|---|-------------|------------------------------------------------------------------------|
| 1 | `--json`    | Машиночитаемый вывод: в stdout только JSON.                             |
| 2 | `--account` | Аккаунт; то же, что позиционное `NAME`. Два разных значения -- ошибка `2`. |

Возвращает `1`, если хотя бы одна проверенная сессия непригодна.

## account -- управление аккаунтами

### account list

Перечисляет аккаунты, у которых есть файл сессии. Опция `--json` даёт
машиночитаемый вывод.

### account default

Без аргумента показывает текущий аккаунт по умолчанию, с аргументом -- задаёт его.
Аккаунт по умолчанию используется всеми командами, вызванными без `--account`.

В stdout уходит только само имя аккаунта, пояснение -- в stderr, поэтому
подстановка вида `NAME=$(tg-export account default)` даёт alias без разбора
строки. Когда аккаунт по умолчанию не задан, stdout пуст, пояснение приходит в
stderr, а код возврата остаётся `0` -- как у `account list` без аккаунтов.
С `--json` печатается объект `{"default": <alias или null>}` -- и при показе, и после задания.

```bash
tg-export account default            # показать
tg-export account default --json     # {"default": "myaccount"}
tg-export account default myaccount  # задать
tg-export account default myaccount --json  # задать и напечатать {"default": "myaccount"}
```

### account remove

Удаляет файл сессии аккаунта. Конфигурация аккаунта и уже сделанная выгрузка
остаются на диске. Возвращает `1`, если аккаунта с таким именем нет.

## config -- показать конфигурацию

Печатает действующие настройки: глобальные (прокси, минимум свободного места) и
по каждому аккаунту, у которого есть файл конфигурации.

| № | Опция             | Назначение                                              |
|---|-------------------|---------------------------------------------------------|
| 1 | `--verbose`, `-v` | Дополнительно показать правила отбора чатов по аккаунтам |
| 2 | `--json`          | Машиночитаемый вывод: каталог конфигурации, прокси, действующий минимум свободного места, число свободных байт, `api_id` и список аккаунтов. С `-v` у каждого аккаунта появляется блок `settings` (каталог и формат выгрузки, типы медиа, предел размера файла, число параллельных загрузок). `api_hash` в этот вывод не попадает: четыре его знака в терминале служат тому, чтобы отличить одни учётные данные от других, и разбирающей программе не нужны. |

## list -- каталог чатов и папок

Запрашивает список диалогов и папок и записывает каталог, из которого затем
строится конфигурация (`init --from-catalog`) или берутся идентификаторы для `tg info`.

```bash
tg-export list --output-file catalog.yaml
tg-export list --json --include-left --output-file catalog.json
```

| № | Опция                 | Назначение                                                             |
|---|-----------------------|------------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт; по умолчанию -- аккаунт по умолчанию.                          |
| 2 | `--output-file FILE`  | Записать в файл. Без опции каталог печатается в stdout. Прежнее написание `--output` принимается. |
| 3 | `--json`              | Плоский JSON вместо YAML; краткая форма `--format json`. Вместе с явным `--format` -- ошибка формы вызова (код `2`): формат назван дважды. |
| 4 | `--format yaml\|json` | Формат: YAML с разделами `folders`/`unfiled`/`archived`/`left` (по умолчанию) либо плоский JSON. |
| 5 | `--include-left`      | Включить покинутые каналы и группы.                                     |

## init -- шаблон конфигурации

Создаёт `~/.config/tg-export/<alias>.yaml` с закомментированным перечнем чатов.
Без `--from-catalog` список запрашивается у Telegram, с `--from-catalog` читается из
ранее выгруженного каталога и обращения к сети не происходит.

```bash
tg-export init --account myaccount
tg-export init --account myaccount --from-catalog catalog.yaml
```

| № | Опция                 | Назначение                                                        |
|---|-----------------------|-------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт, для которого создаётся конфигурация.                      |
| 2 | `--from-catalog FILE` | Каталог, выгруженный командой `list` (YAML с разделами или JSON). Прежнее написание `--from` принимается. |
| 3 | `--output-file FILE`  | Записать конфигурацию по указанному пути вместо пути по конвенции. Прежнее написание `--output` принимается. |
| 4 | `--force`             | Перезаписать существующую конфигурацию; прежняя сохраняется рядом как `<имя>.bak`. |

Существующая конфигурация не перезаписывается: команда завершается кодом 1 и
называет путь. Список чатов со временем меняется, поэтому повторный `init` для
его обновления ожидаем, а написанные руками правила по папкам, лимиты и даты
восстановить неоткуда -- в отличие от сессии и каталога чатов.

## run -- экспорт

Выполняет экспорт по конфигурации аккаунта. При повторном запуске скачиваются
только новые сообщения и файлы.

```bash
tg-export run
tg-export run --dry-run
tg-export run --require-takeout --verify
tg-export run --no-takeout
```

| № | Опция               | Назначение                                                                     |
|---|---------------------|--------------------------------------------------------------------------------|
| 1 | `--account ALIAS`   | Аккаунт; по умолчанию -- аккаунт по умолчанию.                                  |
| 2 | `--config FILE`     | Файл конфигурации вместо пути по конвенции.                                     |
| 3 | `--output DIR`      | Каталог экспорта целиком, вместо `output.path` из конфигурации.                  |
| 4 | `--verify`          | После экспорта проверить целостность скачанных файлов.                          |
| 5 | `--dry-run`         | Показать, что было бы выгружено, ничего не скачивая.                            |
| 6 | `--require-takeout` | Считать недоступность Takeout ошибкой, а не переходить на обычный API.          |
| 7 | `--no-takeout`      | Не запрашивать Takeout вовсе; экспорт идёт через обычный API.                    |
| 8 | `--rerender`        | Пересобрать HTML всех чатов, включая те, в которых ничего не изменилось.         |

Ctrl+C сохраняет состояние и завершает процесс кодом `130`; повторный Ctrl+C
в течение трёх секунд прерывает немедленно. Позже этого окна второй Ctrl+C
читается как новая просьба остановиться мягко: случайное двойное нажатие не
должно отменять чат, который в этот момент сохраняется.

Telegram отвечает на слишком частые запросы задержкой, которую называет сам
(flood wait). На время этой задержки экспорт стоит: счётчики не растут, файлы не
скачиваются. В терминале пауза видна обратным отсчётом в статусной строке
(`waiting: 12s flood wait`); когда живого статуса нет -- вывод перенаправлен или
задан `--quiet` -- вместо отсчёта в журнал пишется строка о начале ожидания.
Отдельных действий такая пауза не требует: по её истечении экспорт продолжается
с того же места.

Ctrl+C печатает ту же сводку, что и завершённый прогон, но под заголовком
`Export interrupted — state saved:`: цифры прерванного прогона от цифр
доведённого до конца ничем другим не отличаются.

Страницы чата пересобираются только тогда, когда прогон что-то в него записал:
рендер каждого чата на каждом запуске означал перечитывание всей базы. Из этого
следует, что после обновления tg-export страницы чатов без новых сообщений
остаются собранными прежней версией шаблонов. `tg-export run --rerender`
пересобирает HTML всех чатов из базы, не обращаясь к Telegram за сообщениями
повторно.

## state -- состояние экспорта

### state show

Показывает по каждому чату: сколько сообщений сохранено, до какого идентификатора
дошёл обход, когда состояние обновлялось в последний раз. С аргументом
`CHAT_ID` -- только по одному чату.

| № | Опция             | Назначение                                        |
|---|-------------------|---------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                          |
| 2 | `--config FILE`   | Файл конфигурации вместо пути по конвенции.        |
| 3 | `--output DIR`    | Каталог экспорта вместо взятого из конфигурации.    |
| 4 | `--json`          | Машиночитаемый вывод: в stdout только JSON.        |

Чат без сохранённого состояния -- законный пустой ответ, а не отказ: команда
печатает `No state for chat <id>` (с `--json` -- `null`) и завершается кодом `0`.
Тем же запросом `state reset` возвращает `1`: сбросить нечего, то есть сделать
то, о чём просили, не удалось.

Базу состояния команда открывает только на чтение и блокировку на неё не берёт,
поэтому состояние видно и во время идущего экспорта. Пишущие команды (`run`,
`state reset`, `import`) блокировку берут и на одной базе парами не работают.

### state reset

Сбрасывает указатели обхода, чтобы следующий запуск перечитал чат с начала.
Сообщения и файлы при этом сохраняются, если не задан `--delete-messages`.
Сброс без него обратим: он стоит повторной выгрузки, а не данных.

Вопрос задаётся во всех случаях, кроме сброса одного чата без
`--delete-messages`: `--all` затрагивает все чаты сразу, поэтому подтверждение
запрашивается и для обратимого сброса. Пропустить вопрос -- `--yes`.

```bash
tg-export state reset 123456789
tg-export state reset --all
tg-export state reset --all --delete-messages --yes
```

| № | Опция                | Назначение                                                   |
|---|----------------------|--------------------------------------------------------------|
| 1 | `--all`              | Сбросить состояние всех чатов.                                |
| 2 | `--delete-messages`  | Дополнительно удалить сохранённые сообщения и записи о файлах из базы. Необратимо: перед удалением печатается число затрагиваемых строк по таблицам и запрашивается подтверждение -- и для одного чата, и для `--all`. |
| 3 | `--yes`              | Не спрашивать подтверждение необратимого сброса -- для автоматизации. |
| 4 | `--account`, `--config`, `--output` | Как у `state show`.                            |

`CHAT_ID` вместе с `--all` отвергается кодом `2` с блоком usage: аргументы просят
разного, а прежде идентификатор молча отбрасывался и сбрасывался весь аккаунт.
Чат без сохранённого состояния даёт код `1` -- в отличие от `state show`, где это
пустой ответ.

## purge -- удалить данные чата

Удаляет данные чата: сообщения и записи о файлах из базы, скачанные файлы и
готовые HTML-страницы с диска. Аргументом принимается идентификатор чата либо
часть названия -- в последнем случае перед удалением показывается найденный чат.

```bash
tg-export purge 123456789
tg-export purge "Рабочий чат" --yes
```

| № | Опция             | Назначение                                          |
|---|-------------------|-----------------------------------------------------|
| 1 | `--yes`           | Не спрашивать подтверждения.                        |
| 2 | `--account`, `--config`, `--output` | Как у `state show`.               |

Перед удалением печатается, сколько записей в каждой таблице будет удалено.

## verify -- проверка скачанных файлов

Сверяет скачанные файлы с записями в базе: файл на месте, размер совпадает.
Битые и отсутствующие файлы скачиваются заново -- во временный каталог рядом с
целевым, с заменой оригинала только после успеха, поэтому обрыв связи не
уничтожает имеющийся файл. Возвращает `1`, если перекачать удалось не всё.

| № | Опция                                | Назначение                    |
|---|--------------------------------------|-------------------------------|
| 1 | `--account`, `--config`, `--output`  | Как у `state show`.           |

## takeout -- сессии Takeout

### takeout clear

Завершает Takeout-сессию на сервере и стирает её идентификатор из файла сессии.
Нужна, когда сохранённый идентификатор мешает: например, требуется начать
выгрузку с другими параметрами Takeout. В обычной работе не требуется --
сессия переиспользуется между запусками намеренно, см. раздел про Takeout в
[README](../README.md).

Если сервер не отвечает (обрыв связи, таймаут), идентификатор остаётся на месте, а
команда завершается кодом `1`: сессия могла остаться запущенной, и сохранённый
идентификатор -- единственный способ к ней вернуться. Повторите команду, когда связь
восстановится. Отказ сервера по существу означает, что сессии там уже нет, и
идентификатор стирается локально.

Аргумент `NAME` задаёт аккаунт; то же значение принимает опция `--account`, общая
с остальными командами. Без них берётся аккаунт по умолчанию; указание двух разных
имён сразу -- ошибка `2`.

## tg -- прямые запросы к Telegram

Команды группы не связаны с экспортом и не пишут в базу состояния.

### tg messages

Печатает последние сообщения чата.

```bash
tg-export tg messages 123456789 -n 20 --no-truncate
```

| № | Опция             | Назначение                                                    |
|---|-------------------|---------------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                                      |
| 2 | `--limit`, `-n`   | Сколько сообщений показать (по умолчанию 10).                  |
| 3 | `--truncate N`    | Обрезать текст до N символов (`0` -- не обрезать, по умолчанию 200). |
| 4 | `--no-truncate`   | Печатать текст полностью.                                      |
| 5 | `--json`          | Машиночитаемый вывод: в stdout массив объектов `id`, `date`, `sender`, `text`, `links`, `media`, `action`, `reply_to`, `reply_to_peer`; заголовок чата уходит в stderr. Обрезка при этом по умолчанию не применяется -- она нужна терминалу; `--truncate N` действует и здесь. Тип медиа и вид системного сообщения стоят отдельными полями, а не приписываются к тексту. Поле `links` перечисляет ссылки, привязанные к словам, поля `reply_to` и `reply_to_peer` связывают ответ с исходным сообщением -- см. ниже. |

Ссылка, привязанная к словам сообщения, хранит адрес вне текста. В строке
для терминала он печатается в скобках сразу за словами ссылки: `см. здесь
(https://example.com/a)`. В `--json` текст остаётся как отправлен, а адреса
идут полем `links` -- списком объектов `offset`, `length`, `text`, `url`.
`offset` и `length` считаются в кодовых единицах UTF-16, как их передаёт
Telegram; `text` -- слова, к которым привязана ссылка. Адрес, набранный в
тексте открытым, в `links` не попадает: он уже виден в `text`.
При обрезке по `--truncate` в `links` остаются только ссылки, целиком попавшие в обрезанный `text`.

Ответ связан с исходным сообщением полем `reply_to` -- номером сообщения, на
которое он отвечает, или `null`, если сообщение ни на что не отвечает. Когда
исходное сообщение лежит в другом чате, `reply_to_peer` называет этот чат
(числовой идентификатор без префикса `-100`), иначе оно `null`. Сообщение в теме
форума ответом на первое сообщение темы не считается. В строке для терминала
ответ отмечен за номером сообщения: `[4711] ↪ 4708`, для другого чата --
`[4711] ↪ 1234567890/4708`.

### tg info

Сведения о чатах: тип, название, число сообщений. Принимает один или несколько
идентификаторов либо каталог с фильтром по типу.

```bash
tg-export tg info 123456789 987654321
tg-export tg info --from-catalog catalog.json --type personal -n 3 --output-file info.json
```

| № | Опция                 | Назначение                                                        |
|---|-----------------------|-------------------------------------------------------------------|
| 1 | `--account ALIAS`     | Аккаунт.                                                          |
| 2 | `--from-catalog FILE` | Каталог в JSON (`list --json`) вместо перечня идентификаторов.     |
| 3 | `--type TYPE`         | Отбор по типу чата; только вместе с `--from-catalog`, иначе ошибка формы вызова (код `2`). |
| 4 | `--limit N`, `-n N`   | Дополнительно показать последние N сообщений каждого чата. Прежнее написание `--last` принимается. |
| 5 | `--output-file FILE`  | Записать результат в JSON-файл. Прежнее написание `--output` принимается. |
| 6 | `--json`              | Машиночитаемый вывод: в stdout только JSON-документ.                |

Возвращает `1`, если хотя бы один чат опросить не удалось, и `2`, если не заданы ни
идентификаторы, ни `--from-catalog`: собрать вызов не из чего. Фильтр `--from-catalog --type`,
не подобравший ни одного чата, -- законный пустой результат: код `0`, а под `--json` в stdout
печатается `[]`. Счётчик обработанных чатов и сообщения об ошибках идут в stderr, поэтому вывод
команды пригоден для конвейера.

### tg send

Отправляет сообщение и файлы одному или нескольким получателям (идентификаторы
или имена пользователей). Требуется хотя бы `--text`, `--text-file` или `--file`.

```bash
tg-export tg send myfriend --text "Привет"
tg-export tg send myfriend --text-file letter.txt
echo "Привет" | tg-export tg send myfriend --text-file -
tg-export tg send 123456789 --file photo.jpg --file video.mp4 --as-document
tg-export tg send 123456789 --file settings.nodepick --as-document --mime-type application/vnd.nodepick+json
tg-export tg send myfriend --text-file letter.txt --schedule "tomorrow 09:00"
tg-export tg send 123456789 --file report.pdf --as-document --schedule +2h
```

| № | Опция               | Назначение                                                             |
|---|---------------------|------------------------------------------------------------------------|
| 1 | `--account ALIAS`   | Аккаунт, от имени которого идёт отправка.                               |
| 2 | `--text`, `-t`      | Текст сообщения. Попадает в командную строку, видимую другим локальным пользователям и истории оболочки. |
| 3 | `--text-file PATH`  | Прочитать текст из файла, а при значении `-` -- со стандартного ввода: текст не проходит через командную строку. |
| 4 | `--parse-mode MODE` | Разметка текста: `md` (Markdown, по умолчанию), `html` или `none` (текст как есть). Элементы -- в разделе [Разметка текста](#разметка-текста). |
| 5 | `--file`, `-f`      | Файл вложения; опцию можно повторять.                                   |
| 6 | `--as-document`     | Отправить файлы без сжатия, как документы: изображения и видео сохраняют исходное качество. |
| 7 | `--mime-type TYPE`  | Тип MIME, который указывается у каждого вложения вместо угаданного по имени файла. Приложение получателя открывает файл по этому типу, если его система не знает типа для расширения: например, `.nodepick` с `application/vnd.nodepick+json` Telegram на Android открывает сразу в nodepick. Файлы с этой опцией уходят по одному, не альбомом. |
| 8 | `--schedule TIME`   | Не отправлять сразу, а поставить сообщение в очередь запланированных сообщений чата: Telegram отправит его в заданное время. Формы времени: `+30m`, `+2h`, `+1d12h` (от текущего момента; единицы `s`, `m`, `h`, `d`, `w`); `10:00` (ближайшие 10:00 -- сегодня, если ещё не наступили, иначе завтра); `tomorrow 10:00`; ISO 8601 `2026-12-31 18:00` или `2026-12-31T18:00+03:00` (без пояса -- местное время). Дата без времени не принимается. |

Команду нельзя запускать, пока идёт экспорт того же аккаунта: файл сессии
рассчитан на одного пользователя, и попытка будет отклонена с указанием, какой
процесс его занял. Возвращает `1`, если хотя бы один получатель не получил сообщение.

После каждого получателя печатается `sent to <получатель> (id <номер>)`, для альбома и нескольких
файлов -- `(ids <номера>)`: эти номера принимает `tg delete`, отдельный `tg messages` не нужен.

С `--schedule` вместо `sent to ...` печатается `scheduled to <получатель> for <время> (scheduled id <номера>)`:
номера -- это номера в очереди запланированных сообщений чата, их принимает `tg scheduled delete`.
Время проверяется до подключения: момент в прошлом, ближе 10 секунд (такое сообщение Telegram
отправил бы сразу, а не запланировал) и дальше 365 дней отвергаются с кодом `2`. Файлы
выгружаются один раз до отправки первому получателю, после чего каждому уходит уже выгруженное.
Время проверяется снова непосредственно перед каждым сообщением: пока шла выгрузка и отправка
предыдущим, момент мог приблизиться. Такому получателю сообщение не отправляется, он засчитывается
как неудачный. Альбом сжатых фото Telethon выгружает сам при отправке, поэтому он выгружается для
каждого получателя заново, а время проверяется перед началом его выгрузки. Отказы
Telegram объясняются текстом: в очереди чата уже около 100 сообщений (предел Telegram), дата слишком
далека или недопустима, планирование для этого аккаунта или чата запрещено.

### tg scheduled list

Показывает очередь запланированных сообщений одного или нескольких чатов -- тех, что поставлены
туда `tg send --schedule` или из приложения Telegram.

```bash
tg-export tg scheduled list myfriend 123456789
tg-export tg scheduled list myfriend --json
```

Для каждого чата печатается число запланированных сообщений и по строке на сообщение: время
отправки в местном поясе, номер в квадратных скобках и текст. Сообщения идут по возрастанию времени
отправки. Номер -- тот, что принимает `tg scheduled delete`.

| № | Опция             | Назначение                                                               |
|---|-------------------|--------------------------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт, чьи запланированные сообщения показываются.                      |
| 2 | `--truncate N`    | Обрезать текст до N символов (`0` -- без обрезки).                        |
| 3 | `--json`          | В stdout массив объектов `chat`, `messages`; у сообщения те же поля, что у `tg messages --json`, и `scheduled_for` -- время отправки с поясом. Обрезка по умолчанию не применяется. |

Возвращает `1`, если очередь хотя бы одного чата прочитать не удалось.

### tg scheduled delete

Удаляет сообщения из очереди запланированных, не отправляя их: названные по номерам или все сразу.

```bash
tg-export tg scheduled delete myfriend 12 13
tg-export tg scheduled delete myfriend --all
```

| № | Опция             | Назначение                                                    |
|---|-------------------|---------------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт, чьи запланированные сообщения удаляются.              |
| 2 | `--all`           | Удалить всю очередь чата вместо перечисленных номеров.         |

Перед удалением очередь читается, и номер, которого в ней нет, печатается как ошибка с кодом `1`:
Telegram о таком номере промолчал бы, и опечатка сошла бы за удаление. Номера и `--all` вместе не
принимаются, как и вызов без того и другого (код `2`).

### tg delete

Удаляет сообщения чата по номерам. Удаление необратимо.

```bash
tg-export tg delete me 4242 4243
tg-export tg delete myfriend 4242 --for-everyone
tg-export tg delete me 4250 --whole-album --yes
```

| № | Опция             | Назначение                                                    |
|---|-------------------|---------------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт, чьи сообщения удаляются.                              |
| 2 | `--for-everyone`  | В личном чате удалить сообщения и у собеседника. По умолчанию они исчезают только у вас. В группах и каналах Telegram удаляет у всех независимо от флага, в «Избранном» (`me`) второй стороны нет. |
| 3 | `--whole-album`   | Если названное сообщение -- часть альбома, удалить все части альбома. |
| 4 | `--yes`           | Удалить без вопроса; список удаляемого всё равно печатается.   |

Номера -- те, что `tg messages` показывает в квадратных скобках, а `tg send` печатает после отправки.
Сначала сообщения читаются через указанный чат и печатаются в stderr: номер, дата, имя файла, начало
текста, пометка `(not yours)` у чужих. Затем строкой сказано, у кого они исчезнут, и задаётся вопрос.
Без терминала на вводе вопрос не задаётся, и команда завершается с указанием на `--yes`.

Номер, которого в чате нет, -- ошибка с кодом `1`, и не удаляется ничего. В личных чатах и малых
группах Telegram принимает номера без чата, и номер сообщения там сквозной. Опечатка удалила бы
сообщение другой переписки, а чтение через чат такие номера отсеивает. Если названа часть
альбома без `--whole-album`, удаляется только она, и вывод перечисляет номера всех частей.
После удаления сообщения читаются снова: если какое-то осталось на месте, например у группы без прав
администратора, это ошибка с его номером. Отказ Telegram в праве удалить тоже даёт код `1`.

### tg edit

Заменяет текст отправленного сообщения или подпись фото, видео и документа.

```bash
tg-export tg edit me 4242 --text-file fixed.md
tg-export tg edit me 4242 --text 'код: `12345`'
tg-export tg edit 123456789 4250 --text-file caption.html --parse-mode html
tg-export tg edit me 4250 --text ''
```

| № | Опция               | Назначение                                                    |
|---|---------------------|---------------------------------------------------------------|
| 1 | `--account ALIAS`   | Аккаунт, чьё сообщение правится.                               |
| 2 | `--text`, `-t`      | Новый текст. Попадает в командную строку, как и у `tg send`.    |
| 3 | `--text-file PATH`  | Прочитать новый текст из файла, при значении `-` -- со стандартного ввода. |
| 4 | `--parse-mode MODE` | Разметка: `md` (по умолчанию), `html`, `none`. См. [Разметка текста](#разметка-текста). |

Новый текст заменяет прежний целиком. У фото, видео и документа это подпись, и пустой текст
(`--text ''`) её снимает; текстовое сообщение пустым не оставляется -- для этого есть `tg delete`.
Пустым считается и текст, в котором после разбора разметки не осталось видимых символов. Сообщение
с превью ссылки -- текстовое, даже если у превью есть картинка. У альбома подпись стоит на одной части, обычно на первой: указывается номер этой части.

Сообщение сначала читается через указанный чат. Номер, которого там нет, и чужое сообщение --
ошибка с кодом `1`, правка не выполняется. В канале чужие посты не отсекаются заранее: админ с
правом правки может менять посты других админов, и решает Telegram. Отказы Telegram объясняются и тоже дают код `1`: истёк
срок, в который Telegram разрешает правку, текст слишком длинный. Если текст совпадает с прежним,
печатается `nothing changed`, код `0`. Запланированные сообщения этой командой не правятся.
Без текста или с `--text` и `--text-file` сразу команда завершается с кодом `2`.

#### Разметка текста

`tg send` и `tg edit` разбирают текст по `--parse-mode`. Номера и идентификаторы удобно
оформлять как код: в приложении Telegram такой фрагмент копируется одним касанием.

| №  | Элемент                  | `md`                       | `html`                                              |
|----|--------------------------|----------------------------|-----------------------------------------------------|
| 1  | полужирный               | `**текст**`                | `<b>текст</b>`, `<strong>`                          |
| 2  | курсив                   | `__текст__`                | `<i>текст</i>`, `<em>`                              |
| 3  | подчёркнутый             | --                         | `<u>текст</u>`, `<ins>`                             |
| 4  | зачёркнутый              | `~~текст~~`                | `<s>текст</s>`, `<del>`, `<strike>`                 |
| 5  | спойлер                  | `\|\|текст\|\|`            | `<tg-spoiler>текст</tg-spoiler>`, `<span class="tg-spoiler">` |
| 6  | код в строке             | `` `12345` ``              | `<code>12345</code>`                                |
| 7  | блок кода с языком       | ```` ```python ```` + строки + ```` ``` ```` | `<pre><code class="language-python">...</code></pre>` |
| 8  | ссылка                   | `[текст](https://host/a)`  | `<a href="https://host/a">текст</a>`                |
| 9  | упоминание пользователя  | `[имя](tg://user?id=42)`   | `<a href="tg://user?id=42">имя</a>`                 |
| 10 | цитата                   | --                         | `<blockquote>текст</blockquote>`                    |
| 11 | сворачиваемая цитата     | --                         | `<blockquote expandable>текст</blockquote>`         |

В `md` нет экранирования: текст, где `**`, `__`, `~~`, `||` или обратные кавычки должны остаться
как есть, отправляется с `--parse-mode none`. В `html` символы `&`, `<`, `>` записываются как
`&amp;`, `&lt;`, `&gt;`. Разметка `md` действовала в `tg send` и до появления опции: по умолчанию
её включает Telethon.

### tg download

Скачивает содержимое одного сообщения: текст в `<msg_id>.txt` и все медиафайлы.

```bash
tg-export tg download 123456789 4242 --output ./downloads
```

| № | Опция             | Назначение                                              |
|---|-------------------|---------------------------------------------------------|
| 1 | `--account ALIAS` | Аккаунт.                                                |
| 2 | `--output`, `-o`  | Каталог для сохранения (по умолчанию текущий).           |
| 3 | `--json`          | Машиночитаемый вывод: в stdout документ `{"chat_id": ..., "msg_id": ..., "text_file": ..., "media": [...]}` с путями сохранённых файлов. |

Имена файлов выбирает Telegram, поэтому пути -- единственный способ узнать, что именно
сохранено: `tg-export tg download 123456789 4242 --json | jq -r '.media[]'`.

Возвращает `1`, если сообщение не найдено.

### tg watch

Слушает чаты и печатает каждое сообщение по мере прихода. Команда не завершается
сама: она держит соединение, пока её не остановят.

```bash
tg-export tg watch --json --log ~/tg-live.ndjson
tg-export tg watch @examplechat 123456789 --json
tg-export tg watch --exclude @noisychat --json
```

Без аргументов слушаются все чаты. Перечень чатов и `--exclude` вместе не
принимаются: Telegram принимает либо белый список, либо чёрный, и
противоречивый отбор отвергается с кодом `2`.

| № | Опция              | Назначение                                                            |
|---|--------------------|------------------------------------------------------------------------|
| 1 | `--account ALIAS`  | Аккаунт.                                                              |
| 2 | `--exclude CHAT`   | Не слушать этот чат; можно повторять. Применяется вместо перечня чатов. |
| 3 | `--json` / `--text`| Формат вывода. По умолчанию `--text` в терминале и `--json` при перенаправлении. |
| 4 | `--log FILE`       | Дописывать каждую запись в файл в формате JSON, независимо от формата вывода в терминал. |
| 5 | `--no-catchup`     | Начать с текущего момента, не добирая пропущенное ни при запуске, ни после восстановления связи. |
| 6 | `--catchup-limit N`| Сколько пропущенных сообщений добирать на чат (по умолчанию 100): берутся последние `N`, более ранние пропускаются с предупреждением в stderr. |
| 7 | `--no-outgoing`    | Не показывать сообщения, отправленные с этого аккаунта, ни в живом потоке, ни при доборе пропущенного. |
| 8 | `--no-edits`       | Не показывать правки и удаления.                                      |
| 9 | `--state FILE`     | Файл отметок прочитанного (по умолчанию `<каталог конфигурации>/watch/<аккаунт>.json`). |

В машинном режиме каждая запись -- отдельная строка JSON (формат NDJSON): строка
разбирается сразу по приходу, а файл журнала дописывается в конец и остаётся
пригодным для разбора после обрыва процесса. Файл журнала держится открытым всё
время работы, поэтому после внешней ротации (переименования файла) записи идут в
переименованный файл, пока `tg watch` не перезапущен.

```json
{"event":"message","chat_id":-1001234567890,"chat":"Рабочая группа","id":4711,
 "date":"2026-09-16 12:03","sender_id":12345,"sender":"Иван Иванов",
 "text":"смотри вложение","links":[],"media":"Document",
 "file":{"name":"отчёт.pdf","size":248000},"action":null,
 "outgoing":false,"reply_to":4708,"reply_to_peer":null}
```

Поле `event` принимает значения `message`, `edited` и `deleted`. У удаления
заполнены `ids` и `date`, а `chat_id` может быть пустым: в личных переписках и
малых группах Telegram не сообщает, где удалено сообщение, -- там достаточно
идентификатора, если получатель сохранил его раньше. По той же причине
`--exclude` не отсекает удаления в таких чатах.

Поля `links`, `reply_to` и `reply_to_peer` устроены так же, как в
`tg messages --json`, а строка для терминала так же печатает адрес ссылки в
скобках за её словами и признак ответа `↪` за номером сообщения.

Вложения не скачиваются: запись называет тип, имя и размер файла, а сам файл
забирает `tg download <чат> <msg_id>`.

Пропущенное добирается по отметкам: команда помнит последнее показанное
сообщение каждого чата и при запуске, а также после восстановления связи,
запрашивает у Telegram только те чаты, где последнее сообщение ушло вперёд
отметки. Где сейчас последнее сообщение, команда узнаёт из списка диалогов: при
названных чатах -- одним запросом только по ним, без обхода всего списка, а без
перечня -- одним проходом по всем диалогам. Чат, который ещё не слушали, историей
не выгружается.

Если в чате пропущено больше `--catchup-limit` сообщений, выдаются последние из
них по возрастанию `id`, а отметка встаёт за последним: более ранние уже не
добираются ни этим запуском, ни следующими. О пропуске команда пишет
предупреждение в stderr с идентификатором чата и границами пропущенного -- после
какого и до какого `id`; в поток записей оно не попадает, формат записей не
меняется.

С `--no-outgoing` свои сообщения не выдаются ни сразу, ни при доборе, но отметка
чата сдвигается и по ним: иначе чат, где последнее сообщение своё, при каждом
запуске выглядел бы непрочитанным. Правки своих сообщений при этом флаге тоже не
выдаются.

Восстановление
связи команда узнаёт сразу, по сигналу Telethon об успешном переподключении, а
не опросом состояния соединения.

Пока догонка не закончилась, новые сообщения печатаются по мере прихода, но
отметку чата не сдвигают: иначе чат выглядел бы прочитанным, а сообщения между
старой отметкой и новым терялись бы. Поэтому во время догонки записи одного
чата могут идти не по возрастанию `id`: сначала пришедшее сейчас, затем
пропущенное. Сообщение, которое уже показал один путь, второй не повторяет.
Если догонка оборвалась, отметки остаются на месте до следующей удачной
догонки, а при завершении команды сохраняются такими, чтобы следующий запуск
добрал пропуск. Аварийное завершение процесса и оборванная догонка могут стоить
повторной выдачи уже показанных сообщений -- потребитель отбрасывает их по полю
`id`.

Слушатель занимает сессию аккаунта на всё время работы, поэтому другая команда
на том же алиасе рядом не запустится: она завершится с кодом `1` и сообщением о
занятой сессии.

#### Слушать и работать одновременно

Блокировка берётся на файл сессии, а алиас в tg-export -- это отдельный файл
сессии, а не отдельный аккаунт Telegram. Поэтому достаточно второй авторизации
того же номера под другим алиасом: слушатель занимает свою сессию, остальные
команды -- свою.

```bash
tg-export auth add --name myaccount-watch        # тот же номер телефона
tg-export tg watch --account myaccount-watch --json --log ~/tg-live.ndjson &
tg-export tg send 123456789 --account myaccount --text "ответ"
tg-export run --account myaccount
```

Отзыва ключа (`AUTH_KEY_DUPLICATED`) при этом не происходит: Telegram отзывает
ключ, когда **один** ключ используется с двух адресов, а у двух авторизаций
ключи разные. Отдельная сессия на каждое место использования аккаунта -- то,
что рекомендует и документация Telethon.

Что следует учесть:

| № | Следствие                                                                 |
|---|---------------------------------------------------------------------------|
| 1 | В Telegram появляется вторая активная сессия -- она видна в «Устройствах»  |
| 2 | Ограничения частоты Telegram считает на аккаунт, а не на сессию: одновременная работа слушателя и экспорта может увеличить паузы |
| 3 | Слушателю конфигурация экспорта не нужна; `run`, `list`, `verify` под этим алиасом потребуют своего файла настроек |
| 4 | Второй алиас появляется в выводе `account list`                           |

Ctrl+C сохраняет отметки и завершает команду с кодом `0`.

## Выбор аккаунта, конфигурации и каталога

Опции повторяются в большинстве команд и разрешаются одинаково:

| № | Что выбирается        | Порядок разрешения                                                                        |
|---|-----------------------|--------------------------------------------------------------------------------------------|
| 1 | Аккаунт               | `--account` > аккаунт по умолчанию (`account default`) > ошибка с подсказкой                |
| 2 | Файл конфигурации     | `--config` > `<каталог конфигурации>/<alias>.yaml`                                          |
| 3 | Каталог конфигурации  | `TG_EXPORT_CONFIG_DIR` > `$XDG_CONFIG_HOME/tg-export` > `~/.config/tg-export`                |
| 4 | Каталог экспорта      | `--output` (путь целиком) > `output.path` из конфигурации с добавлением alias аккаунта       |
| 5 | Уровень логирования   | `--debug` > `--log-level` > `TG_EXPORT_LOG_LEVEL` > `LOG_LEVEL` > `WARNING`                  |

Подробности о каталоге экспорта и о том, когда alias не добавляется, -- в
[configuration.md](configuration.md#output).
