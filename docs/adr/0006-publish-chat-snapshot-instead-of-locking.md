# 0006 — Снимок начала чата вместо блокировки при чтении счётчиков

- Статус: принято
- Дата: 2026-08-22

## Контекст

Живой статус экспорта перерисовывается отдельным потоком `rich.Live`, а счётчики прогона меняет
цикл экспорта в event loop. Поток отрисовки читает и счётчики прогона, и характеристики текущего
чата: сколько сообщений уже в базе, сколько всего, с какого момента идёт чат.

Пока эти значения хранились полями и читались по одному, поток отрисовки мог застать переход
между чатами: итог предыдущего чата уже вычтен, а новые «всего» и «в базе» ещё не записаны. На
экране это давало прогресс больше ста процентов и строку, где данные двух чатов смешаны, — а в
`rich.Progress` значение `completed`, превышающее `total`, роняет отрисовку.

## Рассмотренные варианты

1. Блокировка вокруг чтения и записи счётчиков. Поток отрисовки просыпается несколько раз в
   секунду, а запись идёт на каждое сообщение — это блокировка на горячем пути ради виджета.
2. Копировать значения в поток отрисовки на каждом обновлении. Копию всё равно надо собирать
   согласованно, то есть задача не решается, а переносится.
3. Публиковать состояние начала чата одним неизменяемым объектом, присваиваемым за одну
   операцию, и перечитывать его после вычислений.

## Решение

Принят вариант 3. Начало чата публикуется одним объектом `ChatStart` (снимок счётчиков, число
сообщений в базе, всего и момент старта), который присваивается атрибуту одной операцией. Поток
отрисовки берёт этот объект, вычисляет по нему разности счётчиков и затем перечитывает атрибут:
если он изменился, вычисление повторяется с новым снимком.

Результат отдаётся вызывающему как `ChatView` — неизменяемый объект, все поля которого относятся
к одному и тому же чату.

## Последствия

- Ни блокировок, ни ожидания на горячем пути записи счётчиков: цикл экспорта пишет свои поля так
  же, как раньше.
- Строка статуса и таблица прогресса собираются по одному `ChatView`, а не по нескольким
  независимым чтениям, поэтому смешать данные двух чатов нечем.
- Повтор вычисления в потоке отрисовки возможен, но происходит только в момент смены чата и
  стоит нескольких арифметических операций.
- Требование к дальнейшим правкам: значение, которое читает поток отрисовки, добавляется в
  снимок, а не отдельным полем — иначе гонка возвращается.
