# 0005 — Каталог выгрузки на аккаунт

- Статус: принято
- Дата: 2026-08-22

## Контекст

Каталог выгрузки задаётся в конфигурации полем `output.path`. Аккаунтов у пользователя может
быть несколько, и каждый имеет собственную базу состояния, которая живёт внутри каталога
выгрузки (`.tg-export-state.db`).

Если два аккаунта пишут в один каталог, они делят одну базу состояния: прогресс одного
перезаписывает прогресс другого, а поиск уже скачанных файлов принимает файлы соседа за свои.

При этом конфигурации, написанные прежними версиями, называли каталогом выгрузки сам каталог
аккаунта — добавление алиаса к такому пути дало бы пустой `{path}/{alias}/{alias}` и молчаливый
перезапуск экспорта с нуля.

## Рассмотренные варианты

1. Оставить `output.path` как есть и полагаться на то, что пользователь задаст разные пути.
2. Всегда добавлять алиас аккаунта: `{output.path}/{alias}`.
3. Добавлять алиас, кроме случаев, когда путь уже указывает на каталог аккаунта.

## Решение

Принят вариант 3. Каталогом выгрузки аккаунта считается `{output.path}/{alias}`, кроме двух
случаев, когда путь берётся как есть:

- последний элемент пути уже совпадает с алиасом;
- по указанному пути уже лежит база состояния, то есть это существующая выгрузка.

Шаблон, который печатает `tg-export init`, называет только базовый каталог: алиас добавляется
кодом, и записывать его в конфигурацию не нужно.

## Последствия

- Аккаунты не делят базу состояния и не принимают файлы друг друга за свои.
- Выгрузки аккаунтов лежат рядом в одном родительском каталоге, и переиспользование файлов между
  ними работает по построению: соседний экспорт находится сам.
- Две описанные формы пути остаются рабочими навсегда — иначе обновление версии молча начинало бы
  экспорт заново.
- `--output` переопределяет каталог целиком: указанный путь используется как есть.
