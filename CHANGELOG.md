## [Не выпущено]

### Добавлено

- `-h` работает как синоним `--help` во всех командах и группах: прежде он завершался кодом 2 с сообщением «No such option: -h».
- У `state reset --all` появилось подтверждение и флаг `--yes`. Перед сбросом печатается число затрагиваемых строк по таблицам базы состояния; с `--delete-messages` команда выполняла `DELETE FROM messages` и `DELETE FROM files` по всей базе без показа объёма и без вопроса, а опечатка в команде обходилась повторной выгрузкой всего аккаунта. Сводка печатается как существенная и не подавляется `--quiet`, иначе вопрос задавался бы без единой строки контекста.
- Команда `list` принимает `--json` -- краткая форма `--format json`, одинаковая с `account list`, `auth check`, `state show` и `tg info`.
- Каталог конфигурации подчиняется стандарту XDG Base Directory (`XDG_CONFIG_HOME`) и может быть задан напрямую переменной `TG_EXPORT_CONFIG_DIR`. Прежде путь `~/.config/tg-export` был зашит, и держать раздельные наборы аккаунтов, сессий и учётных данных было нечем: `--config` переопределяет только конфиг аккаунта.
- Инструкция по установке в README приведена в рабочее состояние. Примеры быстрого старта записаны без префикса `uv run`: пакету, установленному из PyPI, каталог проекта недоступен, и первая же команда завершалась ошибкой `Failed to spawn: tg-export`; для работы из исходников префикс объявлен отдельной оговоркой. Установка из исходников описана как `git clone` + `uv sync` -- прежде предлагалась `uv pip install -e .`, которая на свежем клоне падает с `No virtual environment found`, поскольку окружения не создаёт. Установка дополнения для прокси показана в кавычках: в zsh квадратные скобки без них трактуются как шаблон имени файла.
- Скрипт `scripts/check.sh` прогоняет весь набор проверок CI одной командой: `uv lock --check`, `ruff check`, `ruff format --check`, `pyright`, тесты с покрытием и границы покрытия по модулям; `scripts/check.sh --fix` предварительно исправляет исправимое (`ruff check --fix`, `ruff format`). Прежде проверки набирались вручную по трём командам, команда исправления формата нигде не называлась, и шаг `Format check` ломался коммитом, а выяснялось это только на CI. Расхождение скрипта с workflow ловится тестом: шаг, добавленный в CI и не добавленный в скрипт, роняет проверки.
- Релиз проверяется до необратимой публикации. Перед сборкой `publish.yml` прогоняет тот же набор проверок, что и CI на master (`scripts/check.sh`: синхронизация `uv.lock`, линтер, формат, типы, тесты, границы покрытия) -- прежде на релизном пути был только `pytest`, а `ci.yml` на push тега не срабатывает, поэтому тег на коммите с рассинхронизированным `uv.lock` или с ошибками типов публиковался беспрепятственно. Скрипт `scripts/release_notes.py` сверяет имя тега с версией в `pyproject.toml` и наличие непустого раздела в `CHANGELOG.md`, после чего готовит release notes; сверка идёт до загрузки на PyPI, тогда как прежняя проверка `test -s release_notes.md` стояла ниже неё -- отсутствующий раздел давал опубликованную версию, отсутствующий GitHub Release и красный workflow, а отката у PyPI нет.
- Команда `tg info` принимает `--json`: результат по всем чатам выводится в stdout одним документом, как у `account list`, `auth check` и `state show`. Прежде машиночитаемый результат можно было получить только записью в файл (`--output`), в конвейер он не отдавался. Счётчик обработанных чатов переведён в stderr -- `tg info ... | grep` получал вперемешку данные и служебные строки.
- Справочник команд `docs/cli.md`: назначение, опции, поведение и коды возврата всех девятнадцати команд. Прежде документация проводила пользователя только по девяти из них, а `config`, `verify`, `takeout clear`, `tg send`, `tg download`, `state show`, `state reset`, `account list`, `account remove` и `auth check` не были описаны нигде, кроме `--help`. Полнота справочника закреплена тестом: команда, добавленная в код и не описанная в справочнике, роняет проверки.
- Опция `run --require-takeout`: отказ Takeout завершает команду ошибкой вместо перехода на обычный API. Без флага поведение прежнее -- переход выполняется, но теперь он объявляется как существенное сообщение (видно и под `--quiet`), а использованный режим печатается в итоговой сводке строкой `API:`.
- Команда `tg send` принимает `--as-document`: файл отправляется без сжатия, как документ.
- Прогресс отправки файлов в `tg send`.

### Изменено

- Имена флагов приведены к единому соглашению. `--output` везде означает каталог, а файл результата задаётся `--output-file` (`list`, `tg info`); файл каталога чатов во всех командах называется `--from-catalog` (прежде `init --from`); число показываемых сообщений -- `--limit`/`-n` (прежде `tg info --last`). Прежние написания принимаются как синонимы и перечислены в справке, поэтому существующие сценарии не ломаются.
- Опции, выводившиеся в `--help` без описания, описаны: `list --format`, `state show --config/--output`, `state reset --config/--output`. Формулировки взяты те же, что у `run`, `purge` и `verify`. Полнота закреплена тестом: опция без `help=` роняет проверки.
- Идиоматичность кода приведена к тому, что уже принято в проекте. Опции путей объявлены как `click.Path(path_type=Path)` -- параметр приходит в команду уже объектом `Path`, и семнадцать ручных преобразований `Path(...)` после разбора аргументов убраны. Флаги `--quiet`/`--debug` хранятся в одном месте: прежде `main()` писал их и в модульные переменные, и в `ctx.obj`, читались оба хранилища, а `ctx.obj["debug"]` не читался нигде. Стандартная библиотека (`json`, `os`, `shutil`, `subprocess`, `tempfile`, `hashlib`, `unicodedata`, `collections`) импортируется в шапке модуля, а не внутри функций: она уже загружена интерпретатором, а локальный `import logging` вдобавок перекрывал модульный `logger`; отложенными остались только тяжёлые зависимости, и граница закреплена тестом. Цикл событий берётся через `asyncio.get_running_loop()`.
- Контейнерные типы в сигнатурах раскрыты (`dict[str, Any]`, `list[Message]`, `list[TdesktopIndex]` и прочие), для настроек прокси заведён псевдоним `ProxyTuple`, а режим проверки типов поднят с `basic` до `standard`: при «голых» `dict`/`list` pyright выводил `Unknown` и содержимое таких значений не проверял.
- Счётчики по текущему чату собраны в отдельный тип `ChatCounters`. Прежде имена девяти счётчиков были записаны трижды -- как поля, как строковые ключи словаря-снимка и как имена девяти почти одинаковых свойств, -- причём чтение снимка через `.get(..., 0)` превращало опечатку в ключе в молчаливый ноль. Снимок строится по описанию полей, а тест сверяет, что каждому полю `ChatCounters` соответствует счётчик прогона.
- Убраны защитные проверки состояний, невозможных по объявленным типам: снимок активных загрузок берётся у загрузчика напрямую, а не через `getattr` с запасным путём ради тестовых заглушек, поле `is_monoforum` читается как поле. Проверки `isinstance(d, dict)` в начале разбора правил заменены на явную ошибку конфигурации с указанием раздела: `type_rules: {personal: true}` теперь сообщает, что раздел должен быть отображением, а не падает трассировкой `TypeError`. Оба каталога в `ensure_dirs` обрабатываются одинаково -- прежде отказ `chmod` для каталога сессий не перехватывался.
- Имена, которыми пользуются соседние модули, перестали быть приватными: шесть функций сериализации в `models.py` переименованы без ведущего подчёркивания, а состояние завершения экспорта читается через свойства `shutdown_requested`, `force_shutdown` и `shutdown_signal` вместо приватных полей `Exporter`.
- Документация дополнена по итогам сверки с кодом: в схему каталога выгрузки добавлены каталоги `archived/` и `left/`, вложенность монофорумов, страницы глобальных данных и каталоги их файлов; перечень типов медиа без файла дополнен значениями `todo_list`, `giveaway`, `paid_media`, `unsupported`; в справочник конфигурации добавлен раздел о переменных окружения (`TG_EXPORT_CONFIG_DIR`, `LOG_LEVEL`) и приоритете источников -- значения по умолчанию, YAML, окружение, флаги. Из примера в README убрано нереализованное значение `unmatched.action: ask`. Оглавления README и `docs/adr/README.md` дополнены пропущенными разделами.
- Логи библиотек (`telethon`, `aiosqlite`) держатся на уровне `WARNING` независимо от собственного уровня проекта: `--debug` заявлен как быстрый переключатель «показать всё своё», а давал поток пакетных сообщений MTProto, в котором собственные записи терялись. Полный вывод библиотек включается суффиксом `:all` -- `--log-level DEBUG:all` или `LOG_LEVEL=DEBUG:all`.
- Коды возврата приведены к единому правилу: `0` — успех, `1` — команда сообщила об отказе, `2` — ошибка разбора аргументов, `128 + номер сигнала` — прерывание. Раньше кодом `0` завершались `account remove` с неизвестным именем, `auth check` с непригодным аккаунтом, `tg send` при недоставке, `tg download` для отсутствующего сообщения, `state reset` для чата без состояния, `tg info` с ошибками запроса, а также `run` с ошибками экспорта. Прерывание по Ctrl+C вне цикла экспорта теперь тоже даёт `130`, а не `0` или `1`. Таблица кодов добавлена в README.
- Покрытие тестами считается при каждом запуске pytest, а не только в CI, и проверяется не одним общим порогом, а нижними границами по модулям (`scripts/coverage_gate.py`, секция `[tool.tg-export.coverage-floor]`). Общий порог поднят с 45% до 50%.
- Ошибки команды `tg info` печатаются в stderr, а не в stdout: машиночитаемый вывод остаётся пригодным для конвейера.
- Takeout-сессия переиспользуется между запусками, а не создаётся заново каждый раз. Раньше экспорт завершал сессию в `finally` (`stop_takeout(success=True)`), а следующий запуск начинал новую, и Telegram отвечал на неё кулдауном `TAKEOUT_INIT_DELAY` до 24 часов -- то есть Takeout по построению работал не чаще раза в сутки. Теперь сессия открывается с `finalize=False` и по окончании экспорта только отпускается; сохранённый `takeout_id` на следующем запуске проверяется пробным запросом и, если сервер его ещё помнит, используется повторно без нового `InitTakeoutSessionRequest`. Непригодный `takeout_id` завершается и заменяется новой сессией, как прежде. Явное завершение сессии осталось за командой `tg takeout clear`, которая теперь закрывает её и на сервере, а не только стирает локальный идентификатор.
- Убран код, который никем не вызывался: двенадцать функций (`save_takeout`, `get_takeout`, `cache_user`, `get_user`, `get_catalog`, `set_meta`, `get_meta`, `load_messages_for_month` в модуле состояния; `iter_topic_messages`, `get_forum_topics` в обёртке API; `get_chat_names`, `find_files` в импортёре), а также вторая сериализация сообщения `Message.to_json` / `Message.from_json` -- состояние давно хранит поля в отдельных колонках, и обе реализации успели разойтись по составу полей. Из схемы state-БД удалены неиспользуемые таблицы `takeout`, `users_cache`, `meta` и индексы `idx_messages_grouped`, `idx_files_local_path`; у баз, созданных прежними версиями, они убираются при открытии. Форматирование скорости перенесено в `format.format_speed`, чтобы лестница единиц измерения задавалась в одном месте, а девять одинаковых ветвей разметки текста в HTML-рендере свёрнуты в таблицу классов.
- Соединение с Telegram и база состояния открываются через `async with`, а не ручной парой `connect()` / `finally: disconnect()`. Прежде этот блок был повторён в командах десять раз, и в `tg info` и `list` исключение, возникшее между подключением и входом в `try`, оставляло соединение открытым до конца процесса. `TgApi` и `ExportState` стали асинхронными контекстменеджерами; помощник `_connect_tg`, отдававший подключённый объект с оговоркой «вызывающий обязан закрыть», заменён на `_connected_api`, а `_open_state` -- на `_opened_state`. Общий пролог команд (разрешение аккаунта, чтение конфига, вычисление каталога вывода) вынесен в `_resolve_output`: сообщение о ненайденном конфиге больше не живёт в четырёх копиях, расходящихся при правках.
- Разобраны восемь функций длиннее ста строк; самые крупные из них складывались в один сценарий «запустить экспорт»: `Exporter.run` (259 строк), `Exporter.export_chat` (214) и `_run_export` (181). Из `run` выделены установка обработчиков сигналов, отбор чатов, шапка запуска, сборка виджетов прогресса и экспорт одного чата, а три замыкания форматирования статуса стали классом `StatusView`; `export_chat` разделён по границам фаз на `_fetch_new_messages` и `_fetch_old_messages` с отдельным рендером страниц; из `_run_export` вынесены сборка загрузчика и печать итогов. Ни одна функция пакета больше не превышает ста строк, и это закреплено тестом.
- CLI больше не выполняет SQL мимо слоя состояния: сводка по чатам и предпросмотр удаления перед `purge` читаются методами `ExportState.list_chat_states` и `count_chat_rows`. Список таблиц, привязанных к чату, объявлен один раз константой `CHAT_TABLES` -- прежде он был записан дважды, и правка схемы в одном месте давала purge, удаляющий не то, о чём он предупредил.
- Появилась карта пакета для тех, кто меняет код: раздел «Устройство пакета» в `CONTRIBUTING.md` с таблицей из семнадцати модулей, схемой потока экспорта и границами слоёв. У `cli.py` появился модульный docstring с перечнем групп команд и объяснением, зачем импорты сделаны внутри тел функций. Форматирование размеров CLI берёт из `tg_export.format`, а не через приватный псевдоним в `tg_export.exporter`.
- CLI разложен на пакет `tg_export/cli/`: модуль на группу команд (`auth`, `account`, `takeout`, `tg`, `state`) плюс `export` для команд вокруг экспорта и `common` для общего пролога; `__init__.py` собирает группы в `main` и остаётся точкой входа `tg-export`. Прежде весь интерфейс жил в одном файле на две тысячи строк -- вдвое крупнее следующего модуля, -- и часть отложенных импортов существовала именно из-за его размера. Единственный `Console` вывода перенесён из `exporter.py` в `tg_export/console.py`: команда `tg send`, не имеющая отношения к экспорту, тянула ради прогресса отправки весь модуль экспортёра.
- Решение «чем закончить команду» собрано в одном месте. Константы кодов возврата переехали в `tg_export.errors` к иерархии доменных ошибок, у `TgExportError` появился атрибут `exit_code`, и точка входа берёт код из класса ошибки, а не подставляет единицу всей иерархии. Шестнадцать мест выхода сведены к одному помощнику, который печатает отказ и завершает команду через документированный `ctx.exit()`; прежде там стоял `click.exceptions.Exit`, не вынесенный в публичное пространство имён click.
- Предположения о Telethon закреплены тестами. Конвертер ветвится по именам классов (`__class__.__name__`), поэтому переименование класса в библиотеке не давало ни ошибки импорта, ни ошибки типизации -- разбор молча уходил в ветку `unknown`; теперь каждое такое имя сверяется с `telethon.tl.types`. Обход дефекта порядка колонок в файле сессии читает и пишет позиции, поэтому состав и порядок колонок `sessions` и версия схемы тоже проверяются. Шаблон поиска медиа в экспорте Telegram Desktop собирался из множества, и порядок альтернатив зависел от рандомизации хэша строк -- заменён на кортеж.

### Исправлено

- Строка состояния и главная полоса прогресса читают счётчики текущего чата одним согласованным снимком. `begin_chat` присваивал поля по одному, и поток обновления Live успевал прочитать число уже выгруженных сообщений нового чата рядом со снимком предыдущего: полоса показывала выполнено больше, чем всего. Начало чата теперь публикуется одним неизменяемым объектом, а чтение повторяется, если граница чата пришлась на его середину.
- Скорость в строке состояния считается по текущему чату, а не по всему прогону: числитель (байты и сообщения) сбрасывался на каждом чате, а знаменатель продолжал расти с начала запуска, и через час экспорта показанная скорость была занижена в десятки раз.
- Вторая фаза экспорта продолжается с того места, где остановилась первая. Прерывание между фазами оставляет нулевой `oldest_msg_id` при непустом `last_msg_id`, и обход шёл с самого свежего сообщения, то есть чат перебирался целиком заново.
- Проверка файлов сообщает о своих отказах, а не о всех накопленных за прогон: в итог `verify` попадала длина общего списка ошибок, включая ошибки скачивания предыдущих чатов.
- Пути переиспользования файлов (соседний чат того же аккаунта, выгрузка соседнего аккаунта, импорт из tdesktop) сверяют размер уже существующего файла, а не только совпадение имени. Обрыв прошлого прогона оставляет обрезанный файл под тем же именем, и он возвращался как готовый и регистрировался в состоянии со статусом `done`; теперь такой остаток заменяется.
- Покинутые каналы читаются постранично. `GetLeftChannelsRequest` вызывался ровно один раз с `offset=0`, и при числе покинутых каналов больше страницы остальные не попадали в каталог и не обрабатывались правилом `left_channels_action` -- без признаков в журнале.
- Команда `state reset` отличает не переданный идентификатор чата от нулевого: проверка `not chat_id` трактовала `0` как «не задан».
- Возможности, описанные в документации, но не работавшие в коде, приведены в соответствие. `tg-export init --from <каталог>` действительно записывает конфигурацию: прежде команда читала YAML, отбрасывала результат разбора и печатала «Config saved», не создав файла, а следующая команда сообщала «Config not found». Каталог читается и в форме YAML с разделами `folders`/`unfiled`/`archived`/`left`, и в плоской форме JSON; повреждённый файл сообщается как ошибка конфигурации, а не трассировкой. Настройка `defaults.export_service_messages: false` перестала игнорироваться -- служебные сообщения (вход в группу, смена названия, закрепление) больше не попадают в выгрузку, при этом указатели обхода продвигаются и по пропущенным сообщениям, так что повторный запуск не перечитывает их заново. Страница «Прочее» со списком рингтонов управляется одним флагом `profile_music`; ключ `other_data` зарезервирован и это указано в документации. Из допустимых значений убраны нереализованные: `output.format` принимает только `html` (значения `json` и `both` не были реализованы ни в одном пути рендера), `unmatched.action` -- только `skip` и `export_with_defaults` (значение `ask` нигде не обрабатывалось и вело себя как `skip`).
- Экспорт аккаунта идёт в подкаталог с его alias: `output.path` -- базовый каталог, итоговый путь `{path}/{alias}/`, как и было описано в документации. Прежде alias в путь не добавлялся и попадал туда только потому, что шаблон, создаваемый `init`, зашивал его в само значение; конфиг, написанный руками по документации или оставленный со значением по умолчанию `./export_output`, давал двум аккаунтам один каталог, одну базу состояния и переиспользование чужих файлов при дедупликации. Уже сделанные выгрузки остаются на месте: alias не добавляется, если последний элемент пути совпадает с ним или если каталог уже содержит базу состояния. Опция `--output` по-прежнему задаёт каталог экспорта целиком.
- Ошибки экспорта стали наблюдаемыми. Сбой отдельного файла теперь пишется в лог с идентификаторами чата и сообщения и с трассировкой, а не только увеличивает счётчик: прежде «Errors: 137» не поддавалось расследованию ни при каком уровне логирования, потому что исключение не доходило до logging. Итоговая сводка печатает первые десять ошибок и число оставшихся, а не одну цифру. Строка о сбое чата называет тип исключения -- у `TimeoutError` и `ValueError` пустой текст, и сообщение обрывалось на двоеточии. Повторы загрузки перестали быть бесшумными: каждая неудачная попытка пишется на DEBUG с типом ошибки и задержкой, исчерпание попыток -- на WARNING. Ошибки Telegram RPC (`ServerError`, `TimedOutError`) считаются временными и повторяются наравне с сетевыми: они наследуются от `RPCError`, а не от `OSError`, и потому не ретраились вовсе; `FloodWaitError` выжидает объявленное сервером время, а при задержке дольше пяти минут файл отмечается неудачным, не задерживая экспорт. Неудачи выгрузки аватаров, историй и рингтонов считаются и показываются рядом с числом сохранённых (`exported: 10 profile photos, 50 failed`) -- счётчик успеха без счётчика неудач создавал видимость полноты. Тихие переходы к запасному варианту получили запись в журнале: недоступный список покинутых каналов и недоступные частые контакты теперь сообщаются на WARNING, поскольку меняют состав выгрузки.
- Непредвиденная ошибка (Telethon, sqlite, сеть) выводится строкой `Error: <тип>: <текст>` с подсказкой про `--debug`, а не полной трассировкой поверх незакрытого прогресс-бара.
- Ветка двухфакторного входа выбирается по типу исключения Telethon (`SessionPasswordNeededError`, `PasswordHashInvalidError`), а не по подстроке в имени класса. Прежний разбор ломался бы молча при переименовании класса в Telethon: вместо запроса пароля пользователь получил бы трассировку. Заодно посторонняя ошибка входа больше не проходит через ту же ветку -- она распространяется сама, без `else: raise`. Статусные строки логина переведены в stderr: stdout зарезервирован под машиночитаемый вывод команд.
- Неудачный вход больше не оставляет аккаунт без сессии. `auth add` теперь логинится в отдельный файл и занимает штатный путь сессии только после успешного `get_me()`; прежде рабочий файл удалялся до входа, и неверный код, обрыв связи или Ctrl+C на приглашении лишали пользователя и старой сессии, и новой -- восстановить её можно было только повторным полным входом с кодом из Telegram. Соединение закрывается на любом пути выхода, включая прерывание, а файлы неудачного входа убираются. Новый файл сессии сразу получает права `0600`.
- База состояния, созданная прежней версией, приводится к текущей схеме при открытии. Схема создавалась только через `CREATE TABLE IF NOT EXISTS`, а на существующем файле это ничего не меняет: колонка `is_archived`, добавленная в `catalog_cache`, не появлялась, и первая же запись каталога падала с `OperationalError: table catalog_cache has no column named is_archived` -- уже внутри запущенного экспорта. Теперь недостающие колонки добавляются `ALTER TABLE` по фактическому составу таблиц, а ожидаемый состав читается из того же объявления схемы, так что второй список поддерживать не нужно. В файл записывается версия схемы (`PRAGMA user_version`) -- опора для будущих изменений, которые добавлением колонки не решаются.
- Форматирование сообщений с эмодзи больше не теряется и не смещается. Telegram задаёт границы entity (жирный, курсив, ссылки, код) в кодовых единицах UTF-16, а разбор резал Python-строку по кодовым точкам: после первого же символа вне BMP -- любого цветного эмодзи, части иероглифов, музыкальных знаков -- все последующие границы сдвигались, и entity либо не проходила проверку границ и молча отбрасывалась вместе с разметкой, либо вырезала соседний фрагмент, из-за чего подпись ссылки переставала соответствовать её адресу. Разбор переведён на единицы UTF-16.
- `verify` больше не берётся за файлы, пропущенные намеренно. Отбор шёл по условию `status != 'done'`, которое смешивало «не докачано» и «пропущено по размеру или по типу»: команда пыталась перекачать ровно те файлы, которые конфигурация исключила. Заодно в отбор попадают строки с неизвестным размером: сравнение с `NULL` в SQLite даёт `NULL`, а не истину, поэтому такой файл не проверялся никогда.
- Служебные отметки времени в базе состояния (`updated_at`, `downloaded_at`) пишутся в UTC с явным смещением, как и даты сообщений: прежде одинаково объявленные колонки хранили значения двух форматов -- наивное локальное время и момент со смещением, -- что делало их несравнимыми при переносе базы между часовыми поясами. Строки, записанные прежними версиями, сохраняют локальное время.
- Ожидание блокировки базы задано явно (30 секунд) и одинаково для всех соединений: рабочего, read-only-чтения помесячных страниц и поиска файлов в базе соседнего аккаунта. Прежде первые два полагались на умолчание stdlib в 5 секунд, которое соседний код уже считал недостаточным -- на большом батче пишущий процесс удерживает блокировку секундами.
- Из настроек соединения убран `PRAGMA foreign_keys = ON`: внешних ключей в схеме нет, и прагма обозначала защиту, которой не существует. Связи между таблицами поддерживает приложение, что и указано в комментарии к схеме.
- Страницы чата не перерисовываются, когда чат не изменился. Прежде рендер шёл безусловно: все ранее собранные страницы удалялись и строились заново -- с загрузкой каждого месяца из SQLite и разбором JSON-полей каждого сообщения, -- даже если инкрементальный запуск не принёс ни сообщения, ни файла. Теперь рендер запускается, когда за прогон что-то записано либо когда страниц на диске нет.
- Индексная страница читает число сообщений одним запросом на все чаты вместо одного-двух запросов на каждый чат: у аккаунта с сотнями чатов это были сотни обращений к базе на построение одной страницы.
- Служебные запросы к таблице файлов перечисляют нужные колонки вместо `SELECT *`; они выполняются на каждый медиафайл, то есть в самом горячем пути экспорта. Поиск по сообщениям принимает `limit`: отбор по `LIKE '%...%'` индексом не поддерживается, и каждая найденная строка собирается в Message с разбором JSON-полей.
- Границы версий зависимостей приведены к проверенным: `jinja2>=3.1.6` (первый выпуск без пяти уязвимостей, затрагивающих 3.1.0-3.1.5), `click>=8.3.3` (исправлено внедрение команды в `click.edit()`, которую проект не вызывает), `telethon>=1.36,<2` (в Telethon v2 слой сессий переписан, и класса `SQLiteSession`, вокруг которого построен обход ошибки порядка колонок, там нет), `python-socks[asyncio]>=2.0,<3` (Telethon правит приватные внутренности этой библиотеки, а сочетание с вышедшей 3.0.0 не проверялось). В `uv.lock` версии и прежде были безопасными -- границы защищают тех, кто ставит пакет в готовое окружение.
- Конфигурация проверяется при загрузке, а не отказывает молча в середине экспорта. `concurrent_downloads` сверяется с документированным диапазоном 1-5: значение `0` уходило прямо в `asyncio.Semaphore` и подвешивало загрузку медиа без сообщения и без таймаута, строка в кавычках и отрицательное число давали `TypeError`/`ValueError` с трассировкой. `media.types` обязано быть списком известных типов: скаляр `types: photo` превращал проверку вхождения в поиск по подстроке, из-за чего при `types: video_note` скачивались и обычные видео, а опечатка `photos` просто отключала загрузку соответствующих файлов. Ключи `type_rules` сверяются с типами и категориями чатов, записи `import_existing` -- с наличием обоих полей и допустимым `type`. Даты сообщают, в каком поле ошибка, и значение неподходящего типа (`date_from: 2024` читается YAML как число) больше не теряется без предупреждения.
- Глобальный `config.yaml` проверяется наравне с остальными файлами. Опечатка в имени секции (`proxi:` вместо `proxy:`) или прокси, записанный строкой вместо словаря, приводили к подключению напрямую без единого сообщения -- то есть ровно к тому исходу, ради предотвращения которого запуск прерывается при отсутствии `python-socks`. Теперь неизвестный ключ, неверная структура секции и негодные `host`/`port` останавливают команду с объяснением, а неизвестный тип прокси сообщается как ошибка конфигурации, а не трассировкой.
- Синтаксическая ошибка YAML в конфиге аккаунта выводится строкой `Cannot parse <файл>: ...` вместо трассировки.
- `min_free_space: 0` действительно отключает проверку свободного места: значение по умолчанию подставлялось через `or`, поэтому ноль заменялся на 20 ГБ. Само значение по умолчанию объявлено один раз и больше не расходится с тем, что показывает `tg-export config`.
- `~` раскрывается в `output.path` и в `--output`. Прежде запись `path: ~/exports` создавала каталог с именем `~` в текущем рабочем каталоге, и весь экспорт уходил туда.
- Файлы конфигурации читаются в UTF-8, а не в кодировке локали. Имена папок и чатов на кириллице на системе с не-UTF-8 локалью приводили либо к отказу чтения, либо к искажению имён, из-за которого правила молча переставали срабатывать.
- Команда `verify` больше не удаляет битый файл до того, как получит замену. Файл скачивается во временный каталог рядом с целевым и переносится атомарным переименованием только после успеха; обрыв связи или Ctrl+C оставляет прежний файл на месте. Каталоги, оставшиеся от прерванного запуска, убираются при следующем. Команда возвращает `1`, если удалось перекачать не все файлы.
- Потеря `takeout_id` на файлах сессии с физическим порядком колонок `(..., auth_key, tmp_auth_key, takeout_id)`. Telethon пишет строку `sessions` позиционно, поэтому смысл несёт позиция, а не имя колонки; чтение по имени забирало чужие значения, признавало настоящий `takeout_id` мусором и стирало его на каждом запуске, из-за чего режим Takeout не переиспользовался. Чтение переведено на позиции, значение резервируется до обнуления и восстанавливается после, а вся операция идёт в одной транзакции `BEGIN IMMEDIATE`.
- Падение старта на файле сессии схемы `version = 7` с активным Takeout (`TypeError: object supporting the buffer API required`): такая схема больше не пропускается обходом.
- Jinja-шаблоны и статика (CSS, JS, иконки) теперь попадают в дистрибутив. Без `[tool.setuptools.package-data]` в колесо уходили только `*.py`, поэтому любой экспорт после `pip install tg-export` падал с `TemplateNotFound: 'index.html.j2'`; дефект действовал с версии 1.0.0. Smoke-тест перед публикацией больше не ограничивается `--version`: он компилирует все шаблоны установленного пакета и рендерит индексную страницу.
- Прерывание фазы 1 (Ctrl+C) больше не оставляет безвозвратно пропущенный интервал сообщений. Фаза 1 идёт от новых сообщений к старым, поэтому указатель `last_msg_id` продвигается только после её полного прохода; фаза 2 спускается от `oldest_msg_id` и в пропущенный интервал не заходила, так что потерянные сообщения не забирал никто.
- Указатель `last_msg_id` больше не откатывается назад: запись из копии, прочитанной в начале экспорта чата, не может уменьшить уже достигнутое значение. Сброс через `state reset` работает как прежде.
- Удалена вторая, неиспользуемая реализация разметки сообщения. Блок сообщения собирался и шаблонами Jinja, и конкатенацией строк на Python, причём реализации уже разошлись: в шаблонной у отметки времени есть всплывающая подсказка с полной датой, в ручной её не было, а порядок кнопок и реакций был обратным. Работал только шаблонный путь -- ручной вызывался лишь из тестов, поэтому правка «не того» экземпляра проходила проверки, не меняя вывод. Тесты рендера переведены на рабочий путь, где экранирование обеспечивается самим шаблонизатором.
- URL inline-кнопки в HTML-выгрузке проходит проверку схемы: `javascript:` в кнопке попадал в готовую страницу и выполнялся при нажатии. Шаблонный путь такую проверку делал, ручной -- нет. Текст реакции экранируется: это была единственная неэкранированная подстановка в модуле.
- Файлы с секретами и личными данными создаются доступными только владельцу: файл сессии Telegram с ключом авторизации (был `0644`), база состояния с текстами всех сообщений, телефонами и адресами сессий, каталог выгрузки. Ранее созданный пользователем каталог сохраняет свои права -- он мог быть открыт намеренно. Права `config.yaml` с логином и паролем прокси проверяются так же, как у `api_credentials.yaml`: слишком широкие сужаются с записью в журнал.
- Ввод `api_hash` при `auth credentials` скрывается: набранный в открытую, он остаётся в истории оболочки.
- Имя аккаунта проверяется перед подстановкой в путь файла сессии и конфигурации: разделитель пути или ссылка на родительский каталог в имени размещали и удаляли файлы за пределами каталога настроек.
- Путь к базе соседнего аккаунта экранируется при сборке SQLite-URI: символ `?` в пути превращал остаток в параметры и снимал режим «только чтение».
- Файл блокировки состояния больше не удаляется при освобождении. `flock` привязан к inode, а не к имени: удаление позволяло процессу, успевшему открыть файл, удерживать блокировку на осиротевшем inode, пока следующий создавал новый файл и брал блокировку на нём. Два экспорта работали с одной базой состояния, взаимно удаляя файлы при уборке и затирая указатели.
- Файл сессии Telegram защищён собственной блокировкой. Прежняя блокировка привязана к каталогу вывода, поэтому не мешала ни `tg send` рядом с идущим экспортом, ни второму экспорту с другим `--output`: обе команды работали с одной сессией, а Telethon отвечает на это порчей ключа авторизации в файле. Теперь вторая команда сообщает, что сессия занята.
- Принудительное завершение (второй Ctrl+C подряд) снимает только задачу экспорта. Раньше отменялись все задачи цикла событий, включая внутреннюю задачу `asyncio.shield`, то есть ровно ту защиту, ради которой shield и поставлен: запись пачки сообщений и удаление данных чата могли остаться применёнными наполовину.
- Защищённая запись удерживает вызывающего до своего конца. `asyncio.shield` защищает операцию, но не вызывающего: тот получал отмену немедленно, доходил до закрытия соединения, и идущий commit падал в неотловленной задаче с `ValueError: Connection closed`.
- Команда `run` освобождает файл блокировки состояния и соединение, если отказ случился между их захватом: раньше оба захватывались до блока, который их освобождает.
- Установка обработчиков сигналов не роняет экспорт на платформах, где она не поддерживается (Windows): там Ctrl+C приходит обычным прерыванием, которому команда и так сопоставляет код `130`.
- Блокирующие операции вынесены из потока цикла событий. Поиск файла в базе соседнего аккаунта открывал SQLite обычным `sqlite3` и мог ждать занятого писателя до 30 секунд; копирование файла из выгрузки tdesktop и запасная ветка связывания между чатами читали и писали файл целиком; страницы глобальных данных и индекс собирались шаблонизатором при живом соединении с Telegram. Всё это время не обслуживались ни соседние загрузки, ни соединение. Рендер чата так работал и раньше. Свободное место проверяется не на каждый файл, а не чаще раза в пять секунд; неудачная проверка не кешируется.
- Загрузки медиа внутри чата идут параллельно, как обещают настройка `concurrent_downloads` и документация. Раньше загрузка ожидалась прямо в теле цикла по сообщениям, поэтому одновременной оставалась ровно одна: между файлами вставлялся полный цикл «запрос -- ответ» к серверу Telegram, а пока файл скачивался, итератор не запрашивал следующую пачку сообщений. Мёртвыми при этом были и семафор, и пофайловые блокировки, и защита списка активных загрузок. Сообщение по-прежнему попадает в базу только после своей загрузки и в прежнем порядке: ожидается всегда самая старая из идущих загрузок.
- Уборка после неудачной загрузки удаляет только собственные недокачанные файлы. Раньше удалялось всё, что появилось в общем каталоге чата с момента снимка, снятого ещё до постановки в очередь загрузки, так что при одновременных загрузках сносились файлы, только что дописанные соседней. Каждая загрузка идёт в свой временный подкаталог и переносится на место готовой; каталоги, оставшиеся от прерванного запуска, убираются при первом обращении к целевому каталогу. При совпадении имён свободное имя подбирается так же, как это делал Telethon.
- Прогресс отправки (`tg send`) не рисуется, когда вывод не является терминалом: раньше проверялся только `--quiet`, и при перенаправлении в файл или конвейер туда попадали перерисовки бара. Экспорт делал такую проверку с самого начала.
- Прогресс альбома больше не уходит за 100%. Telethon режет альбом на группы по десять и передаёт в обратный вызов остаток списка (25, затем 15, затем 5), тогда как счётчик отправленного считается от начала альбома; это значение перетирало общее число файлов. Теперь общее число задаётся один раз и берётся из самого списка.
- Вид полосы прогресса одинаков в обоих режимах отправки: проценты показываются и при побайтовом счёте, и при альбомном, а размер и скорость добавляются к ним, когда счёт идёт по байтам. Раньше одна и та же команда выглядела по-разному в зависимости от числа файлов.
- Имя файла в прогрессе отправки (`tg send`) экранируется перед выводом. rich разбирает описание задачи как разметку, поэтому имя вида `[draft]report.txt` печаталось как `report.txt`: квадратные скобки съедались вместе с содержимым. Используется та же функция экранирования, что и в прогрессе загрузки при экспорте.
- Флаг `--quiet` больше не глушит причину отказа. Признак «существенное сообщение» проставлялся вручную у отдельных вызовов, и из 94 мест его имели 20, причём 17 из них -- строки итоговой сводки; в результате `--quiet tg send 123` печатал пустой вывод и возвращал `1`, а одно и то же сообщение `Config not found` было видно в `run` и терялось в `state show`, `state reset` и `verify`. Все сообщения, за которыми команда завершается ошибкой, выводятся через отдельную функцию и переживают `--quiet`; статическая проверка не даёт новому пути отказа снова оказаться подавленным. Команда `purge` под `--quiet` показывает описание удаляемого перед запросом подтверждения: вопрос без описания предмета ответить нельзя.
- Ограничение размера файла для Takeout-сессии считается по всем применимым правилам, а не только по `defaults.media`. Разделы `chats`, `type_rules` и `folders` задают собственный `max_file_size`, и значение выше умолчания урезалось самой сессией: Takeout несёт один лимит на всё время жизни. Теперь берётся максимум из умолчания и лимитов правил, которые действительно приводят к скачиванию (правила со `skip`, а также вложенные чаты пропущенной папки, в расчёт не идут).
- Диагностика состояния файла сессии различает три разных состояния вместо одной строки на все. Сообщение «Detected stale takeout_id/tmp_auth_key ... staging restore» печаталось при каждом запуске, включая полностью исправный: Telethon при `store_tmp_auth_key_on_disk = false` всегда пишет в `tmp_auth_key` пустое значение, поэтому признак «в строке что-то есть» был истинным всегда, а восстанавливать при этом было нечего. Теперь перенос настоящего `takeout_id` сообщается на уровне INFO с указанием значения, штатное пустое значение уходит в DEBUG и не создаёт лишней записи в резервной таблице, а предупреждение о непригодном значении называет источник (строка `sessions` или отложенная копия) и поясняет, чем разовая санация отличается от повреждения, возникающего снова на каждом запуске.
- Интерактивный логин (`account add`) открывает файл сессии через `FixedSQLiteSession`, а не по строковому пути. Строка заставляла Telethon построить обычный `SQLiteSession`, который адресует колонки таблицы `sessions` по имени, тогда как записываются они позиционно; логин оставался единственным писателем вне защиты и потому источником повторного повреждения файла.
- Отказ Takeout больше не поглощается широким `except Exception` -- обрабатываются только ошибки, которые действительно означают недоступность Takeout, а дефекты кода доходят до вызывающего.

- `register_file` теперь явно делает `commit`: при kill -9 файл не остаётся незарегистрированным в БД.
- `_verify_files` использует тот же путь `register_file -> commit`, поэтому verify-результаты сохраняются и не теряются при `close()`.
- `_handle_shutdown` через `asyncio.shield` защищает идущий `commit` от отмены: повторный SIGINT не теряет batch до 500 сообщений.
- `_cleanup_orphaned_files` сравнивает абсолютные resolved-пути; запуск из другой cwd больше не приводит к удалению легитимных файлов как orphaned.
- `_download_if_new` сравнивает SHA-256 первых 64KB, а не только размер: два разных файла одной длины больше не схлопываются в один.
- `start_takeout` отлавливает `TakeoutInvalidError`/`TakeoutRequiredError` напрямую, а не через подстроку в `str(e)`.
- `cache_catalog` явно коммитит запись о чате: статистика не теряется, если экспорт прервался до первого batch-commit.
- Сообщение об отсутствии default-аккаунта указывает правильную команду `tg-export account default`, а не несуществующую `auth default`.

### Добавлено

- SQLite PRAGMA: `journal_mode=WAL`, `synchronous=NORMAL`, `cache_size=-65536`, `mmap_size=268435456`, `temp_store=MEMORY`, `foreign_keys=ON`.
- Lock-файл `<state>.db.lock` через `fcntl.flock`: защита от случайного второго процесса экспорта над одной БД.
- Стриминговый рендер по месяцам через `render_chat_streaming`: пиковая память пропорциональна одному месяцу, а не всему чату.

- Индексы SQLite: `idx_files_chat`, `idx_files_status`, `idx_files_local_path`, `idx_messages_grouped`.
- `state.list_message_months`, `state.load_messages_for_month`, `state.get_catalog_entry`.
